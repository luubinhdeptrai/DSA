# JDBC + PostgreSQL Mini Project

This project builds a small console application called **Student Management JDBC**. Its purpose is to make the raw JDBC flow visible from database setup through CRUD, generated keys, batch insertion, and one atomic account transfer.

Technologies:

```text
Java 17+ + Maven + JDBC + Docker Compose + PostgreSQL
```

Infrastructure boundary:

```text
Windows / macOS / Linux host
├── Java + Maven application
└── Docker
    └── PostgreSQL container only
```

There is no Java `Dockerfile` and no Java application container. Also not used:
Spring, Spring Boot, JPA, Hibernate, web servers, REST, or persistence helper
libraries. Docker is used only to run PostgreSQL.

> The instructions, starter shapes, TODOs, and hints come first. The complete code is intentionally delayed until section 27.

---

## 1. Project Goal

> Priority: ⭐⭐⭐⭐⭐ MUST KNOW practice

Build a plain Java console application that can:

- connect reliably to PostgreSQL running in Docker and published on `localhost`;
- create, find, list, update, and delete students;
- retrieve the ID generated by PostgreSQL;
- report meaningful `SQLException` details;
- insert several students with a prepared batch;
- transfer money between two accounts in one transaction;
- keep SQL/JDBC code in DAO/service classes instead of `main()`.

The final learning flow is:

```text
Docker and Compose verified
        ↓
compose.yaml
        ↓
PostgreSQL container + named volume
        ↓
jdbc_app user + jdbc_practice database initialized
        ↓
tables created manually with SQL
        ↓
Java Maven application on host
        ↓
java.sql API → pgJDBC
        ↓
localhost:5432 → Docker port mapping
        ↓
PostgreSQL container
        ↓
jdbc_practice database → students / accounts
        ↓
CRUD + generated keys + batch + transaction
        ↓
working console application
```

Expected time is approximately **3–6 focused hours**, depending on the first
Docker image download and how much code you write before consulting hints.

## 3. Final Architecture

> Priority: ⭐⭐⭐⭐⭐ MUST KNOW

Write path:

```text
Main (host console input/output)
        ↓
StudentDAO / AccountTransferService
        ↓
PreparedStatement + bound parameters
        ↓
JDBC Connection (`java.sql`)
        ↓
PostgreSQL JDBC driver (pgJDBC)
        ↓ TCP
jdbc:postgresql://localhost:5432/jdbc_practice
        ↓
host port 5432
        ↓ Docker mapping 5432:5432
PostgreSQL container port 5432
        ↓
jdbc_practice database
```

Read path:

```text
PostgreSQL container
    ↓
ResultSet
    ↓
StudentDAO.mapRow(...)
    ↓
Student object / List<Student>
    ↓
Main
```

Configuration path:

```text
environment variables (preferred override)
or ignored local database.properties
             ↓
DatabaseConfig
             ↓
DriverManager.getConnection(...)
```

The transaction service owns its connection because debit and credit must share one transaction. Ordinary student CRUD methods each own one short-lived connection.

`localhost` is correct because the Java process runs on the host machine and
Docker publishes the container's PostgreSQL port to host port `5432`.

> **Future knowledge only:** If Java later ran inside another Compose service, it
> would normally connect to `postgres:5432`, where `postgres` is the service name.
> That hostname is wrong for this project because Java is not containerized.

## 5. PostgreSQL Setup

> Priority: ⭐⭐⭐⭐⭐ MUST KNOW setup

### 5.1 Create the project directory and `compose.yaml`

Create `jdbc-postgresql-practice`, enter it, and create this `compose.yaml` in
the project root:

```yaml
services:
  postgres:
    image: postgres:17
    container_name: jdbc-postgres
    environment:
      POSTGRES_DB: jdbc_practice
      POSTGRES_USER: jdbc_app
      POSTGRES_PASSWORD: change_me_local_only
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

This uses the official PostgreSQL image and pins the supported stable major
version `17` rather than the moving `latest` tag. The major tag receives newer
PostgreSQL 17 maintenance releases when the image is pulled. PostgreSQL 18+
uses a different official-image volume layout, so do not change only the image
tag without also reading that version's official image notes.

The credentials shown here are **development-only / learning-only**. They are
acceptable for this disposable local exercise. Real production secrets should
not normally be committed directly in Compose files.

### 5.2 Understand the Compose fields

First, the minimum Docker vocabulary:

```text
image
→ packaged template containing PostgreSQL

container
→ created, runnable instance of that image; it may be running or stopped

Docker Compose
→ reads compose.yaml and manages the project

service
→ named Compose configuration for one kind of container
```

| Field | Beginner meaning |
|---|---|
| `services` | Programs Compose manages for this project |
| `postgres` | Service name used by commands such as `docker compose logs postgres` |
| `image` | Official PostgreSQL server image; `postgres:17` pins the major version |
| `container_name` | Readable fixed container name, `jdbc-postgres` |
| `environment` | Values passed to the image's initialization process |
| `POSTGRES_DB` | Initial database name: `jdbc_practice` |
| `POSTGRES_USER` | Initial PostgreSQL user: `jdbc_app` |
| `POSTGRES_PASSWORD` | Password assigned to that initial user |
| `ports` | Publish host port `5432` to container port `5432` |
| service `volumes` | Mount persistent storage at PostgreSQL 17's data directory |
| top-level `postgres_data` | Declare a Docker-managed named volume |

In this simple official-image setup, `POSTGRES_USER=jdbc_app` creates the initial
PostgreSQL superuser. That shortcut is acceptable only for this learning
environment. A production design normally separates an administrative/migration
owner from a least-privileged runtime role.

### 5.3 Understand why the JDBC URL still uses `localhost`

```text
Java application on host machine
        ↓
jdbc:postgresql://localhost:5432/jdbc_practice
        ↓
host port 5432
        ↓ Docker mapping "5432:5432"
container port 5432
        ↓
PostgreSQL container
        ↓
jdbc_practice database
```

The left side of `5432:5432` is the **host port**; the right side is the
**container port**. Java runs on the host, so it connects to `localhost` and the
published host port. Do not change this project's URL to
`jdbc:postgresql://postgres:5432/...`; `postgres` is a Compose-network hostname
for another container, and Java is not in a container here.

The short `"5432:5432"` form can publish the database on all host network
interfaces, even though this Java application uses `localhost`. On a shared or
untrusted network, prefer the loopback-only form
`"127.0.0.1:5432:5432"`. This guide retains the requested short mapping for the
exercise; do not treat its learning password as protection for an exposed
production database.

### 5.4 Start and verify PostgreSQL

Run beside `compose.yaml`:

```bash
docker compose up -d
docker compose ps
docker compose logs postgres
docker compose exec postgres pg_isready -h 127.0.0.1 -p 5432 -U jdbc_app -d jdbc_practice
```

| Command | What it does |
|---|---|
| `docker compose up -d` | Creates/starts the service, network, and volume as needed, then runs in the background |
| `docker compose ps` | Shows service state and published ports |
| `docker compose logs postgres` | Shows PostgreSQL initialization, startup, and errors |
| `docker compose exec ... pg_isready` | Runs the image's readiness client inside the running container |

`up -d` returning successfully means Compose started the container; PostgreSQL
may still be initializing. Continue after the logs include that the database
system is ready to accept connections and `pg_isready` reports it is accepting
connections.

`pg_isready` checks whether the final TCP listener accepts connections; it does
not authenticate the supplied username/password. Task 1's Java connection is
the authoritative test of the host-published route and password.

### 5.5 Understand first initialization

The official image uses the three `POSTGRES_*` values only when initializing an
**empty PostgreSQL data directory**:

```text
empty postgres_data volume
        ↓
official image reads POSTGRES_USER / PASSWORD / DB
        ↓
creates initial jdbc_app user
        ↓
creates jdbc_practice database
        ↓
later starts reuse the existing database files
```

Therefore, do not manually run `CREATE ROLE jdbc_app` or
`CREATE DATABASE jdbc_practice`; Compose has already initialized them. You will
still write and run `CREATE TABLE` statements in section 6.

Keep the database hierarchy in mind:

```text
PostgreSQL server
├── roles/users
└── databases
    └── schemas
        └── tables
```

### 5.6 Open `psql` inside the container

No host `psql` installation is required:

```bash
docker compose exec postgres psql -U jdbc_app -d jdbc_practice
```

This command normally uses PostgreSQL's local socket inside the container and
may not prompt for a password. It proves that the server, user, and database
exist; the host Java connection test still proves the published TCP route and
password authentication.

```text
docker compose exec
        ↓ runs a command in the existing postgres service container
psql
        ↓ connects inside that container
PostgreSQL → jdbc_practice
```

Useful `psql` commands:

| Command | Purpose |
|---|---|
| `\conninfo` | Show the current connection |
| `\dt` | List tables in the current search path |
| `\d students` | Describe the students table after creation |
| `\q` | Quit `psql` |

Backslash commands are `psql` commands, not SQL; do not add semicolons to them.

### 5.7 Stop, start, remove, and preserve data

Routine lifecycle commands:

```bash
docker compose stop
docker compose start
docker compose down
```

Destructive full-removal command:

```bash
docker compose down -v
```

> ⚠ **Destructive — practice project only:** `-v` removes the named volume and
> all roles, databases, tables, and rows stored in it. Never use it casually
> against data you need.

| Command | Container/network result | Named volume/data result |
|---|---|---|
| `docker compose stop` | Existing container is kept but stopped | Kept |
| `docker compose start` | Starts that existing stopped container | Kept |
| `docker compose down` | Containers and Compose network are removed | Kept |
| `docker compose up -d` after `down` | Container/network are recreated | Existing named-volume data is reused |
| `docker compose down -v` | Containers/network are removed | **Deleted** |

After `docker compose down`, use `docker compose up -d`, not `start`, because
`down` removed the container. `start` works only for a container retained by
`stop`.

```text
PostgreSQL container can be removed
        ↓
postgres_data named volume remains
        ↓
database files survive
        ↓
new container mounts the same files
```

The mapping
`postgres_data:/var/lib/postgresql/data` is what keeps PostgreSQL 17's database
files outside the disposable container layer.

## 6. Database and Table Creation

> Priority: ⭐⭐⭐⭐⭐ MUST KNOW SQL setup

Run the following inside the container `psql` session from section 5, connected
to `jdbc_practice` as `jdbc_app`.

### 6.1 Students table

```sql
CREATE TABLE students (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL CHECK (btrim(name) <> ''),
    email VARCHAR(150) UNIQUE NOT NULL,
    age INTEGER NOT NULL CHECK (age BETWEEN 0 AND 150),
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

| Column | Meaning |
|---|---|
| `id` | PostgreSQL generates a 64-bit identity value; primary key makes it unique/non-null |
| `name` | Required, up to 100 characters, and not whitespace-only |
| `email` | Required and unique; duplicate inserts raise a constraint error |
| `age` | Required integer constrained to a simple learning range |
| `created_at` | Server-generated creation timestamp with time-zone semantics |

The prompt's `BIGSERIAL` example is still common and valid. `GENERATED ... AS IDENTITY` is the modern SQL-standard style and is used here.

Verify:

```sql
SELECT current_database(), current_user;
SELECT id, name, email, age, created_at FROM students;
```

In psql, describe the table separately:

```text
\d students
```

### 6.2 Accounts table for the transaction exercise

```sql
CREATE TABLE accounts (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    owner_name VARCHAR(100) NOT NULL,
    balance NUMERIC(15, 2) NOT NULL CHECK (balance >= 0)
);

INSERT INTO accounts (owner_name, balance)
VALUES
    ('Account A', 1000.00),
    ('Account B', 500.00);
```

`NUMERIC(15,2)` stores exact decimal values. Java will bind the transfer amount with `BigDecimal`, not `double`.

Verify and record the two generated IDs:

```sql
SELECT id, owner_name, balance
FROM accounts
ORDER BY id;
```

### 6.3 Reset application rows only

If you need to reset the rows while keeping the database, tables, container, and
named volume:

```sql
TRUNCATE TABLE students RESTART IDENTITY;
TRUNCATE TABLE accounts RESTART IDENTITY;

INSERT INTO accounts (owner_name, balance)
VALUES ('Account A', 1000.00), ('Account B', 500.00);
```

`TRUNCATE` is destructive. Run it only against this confirmed practice database, never casually against real data.

### 6.4 Reset the entire PostgreSQL learning environment

For a completely fresh **disposable practice** database:

```bash
docker compose down -v
docker compose up -d
```

```text
down -v
→ destroys the PostgreSQL named volume and everything in it

up -d
→ creates a fresh volume
→ initializes jdbc_app and jdbc_practice from compose.yaml
```

> ⚠ **Destructive — practice project only:** This deletes both tables and all
> rows. Because this guide deliberately keeps schema SQL visible instead of using
> an automatic `init.sql`, you must reopen in-container `psql` and rerun all table
> and seed SQL from section 6 after the reset.

## 8. PostgreSQL JDBC Dependency

> Priority: ⭐⭐⭐⭐⭐ MUST KNOW

The dependency coordinates are:

```text
org.postgresql:postgresql:42.7.13
```

The first Maven build normally performs:

```text
read pom.xml
      ↓
resolve pgJDBC from configured repository (normally Maven Central)
      ↓
download JAR and POM metadata
      ↓
cache under ~/.m2/repository
      ↓
put driver on runtime classpath for exec:java
      ↓
DriverManager discovers PostgreSQL driver
```

Why `runtime` scope is correct here:

- Source code imports `java.sql.*`, which comes from the JDK.
- No source file imports `org.postgresql.*`.
- The vendor driver is required when the application actually connects.

Confirm resolution:

```bash
mvn dependency:tree
```

Look for:

```text
org.postgresql:postgresql:jar:42.7.13:runtime
```

If you later import a pgJDBC-specific class directly, change to the default `compile` scope or deliberately restructure around a standard `DataSource` supplied by configuration.

Docker and pgJDBC remain separate requirements:

```text
Docker
→ runs the PostgreSQL server

pgJDBC Maven dependency
→ implements Java-to-PostgreSQL communication
```

Docker does not replace the JDBC driver, and the JDBC driver does not run the
database server.

3. Let environment variables override properties.

### DAO hints

1. Store SQL as `private static final String` constants.
2. Let CRUD methods declare `throws SQLException`.
3. A method that opens a connection owns/closes it.
4. `findAll()` creates the list before its resource block and returns it afterward.

### Generated-key hints

1. Request keys while preparing, not after execution.
2. Verify affected count before reading keys.
3. `getGeneratedKeys()` is a `ResultSet` and begins before its first row.

### Batch hints

1. Bind all three values, then `addBatch()`, once per student.
2. Call `executeBatch()` after the loop.
3. Disable auto-commit before preparing/executing the atomic batch.
4. Commit after success; rollback after `SQLException` or runtime failure.
5. Do not assign generated IDs in this batch task; `create()` separately practices keys.

### Transaction hints

1. Validate IDs/amount before opening the connection.
2. Both prepared statements must be created from the same connection.
3. Require debit count and credit count to equal 1.
4. A safe debit also checks `balance >= amount` in its `WHERE` clause.
5. If rollback fails, attach that failure with `original.addSuppressed(...)`.
6. A directly opened connection closes after the method; a future pooled version must also return clean state.

### Console hints

1. Use a small method per menu action.
2. Parse `nextLine()` values with `Long.parseLong`, `Integer.parseInt`, and `new BigDecimal`.
3. Catch SQL failure at the menu boundary, not inside every DAO method.
4. Use a timestamp in batch email addresses so rerunning does not create accidental duplicates.

### 27.4 Complete `DatabaseConfig.java`

```java
package com.example.jdbc.config;

import java.io.IOException;
import java.io.InputStream;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.util.Properties;

public final class DatabaseConfig {

    private static final String CONFIG_FILE =
            "database.properties";

    private static final Properties PROPERTIES =
            loadProperties();

    private DatabaseConfig() {
    }

    public static Connection getConnection()
            throws SQLException {
        return DriverManager.getConnection(
                requiredValue("DB_URL", "db.url"),
                requiredValue("DB_USERNAME", "db.username"),
                requiredValue("DB_PASSWORD", "db.password")
        );
    }

    private static Properties loadProperties() {
        Properties properties = new Properties();

        try (InputStream input = DatabaseConfig.class
                .getClassLoader()
                .getResourceAsStream(CONFIG_FILE)) {

            if (input != null) {
                properties.load(input);
            }

            return properties;
        } catch (IOException e) {
            throw new IllegalStateException(
                    "Could not read " + CONFIG_FILE,
                    e
            );
        }
    }

    private static String requiredValue(
            String environmentName,
            String propertyName
    ) {
        String value = System.getenv(environmentName);

        if (value == null || value.isBlank()) {
            value = PROPERTIES.getProperty(propertyName);
        }

        if (value == null || value.isBlank()) {
            throw new IllegalStateException(
                    "Missing configuration: " + propertyName
                            + " (or environment variable "
                            + environmentName + ")"
            );
        }

        // Do not log or print this value; it may be the password.
        // It is not trimmed because a password may contain whitespace.
        return value;
    }
}
```

No explicit `Class.forName("org.postgresql.Driver")` is needed. pgJDBC registers through the modern JDBC service-provider mechanism when present on the runtime classpath.

### 27.6 Complete `StudentDAO.java`

```java
package com.example.jdbc.dao;

import com.example.jdbc.config.DatabaseConfig;
import com.example.jdbc.model.Student;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import java.util.ArrayList;
import java.util.List;

public class StudentDAO {

    private static final String INSERT_SQL = """
            INSERT INTO students (name, email, age)
            VALUES (?, ?, ?)
            """;

    private static final String FIND_BY_ID_SQL = """
            SELECT id, name, email, age
            FROM students
            WHERE id = ?
            """;

    private static final String FIND_ALL_SQL = """
            SELECT id, name, email, age
            FROM students
            ORDER BY id
            """;

    private static final String UPDATE_SQL = """
            UPDATE students
            SET name = ?, email = ?, age = ?
            WHERE id = ?
            """;

    private static final String DELETE_SQL =
            "DELETE FROM students WHERE id = ?";

    public long create(Student student) throws SQLException {
        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(
                             INSERT_SQL,
                             Statement.RETURN_GENERATED_KEYS
                     )) {

            bindStudent(statement, student);

            int affectedRows = statement.executeUpdate();
            if (affectedRows != 1) {
                throw new SQLException(
                        "Expected one inserted row, got "
                                + affectedRows
                );
            }

            try (ResultSet keys =
                         statement.getGeneratedKeys()) {
                if (!keys.next()) {
                    throw new SQLException(
                            "Insert succeeded, but no generated ID "
                                    + "was returned"
                    );
                }

                long id = keys.getLong(1);
                student.setId(id);
                return id;
            }
        }
    }

    public Student findById(long id) throws SQLException {
        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(FIND_BY_ID_SQL)) {

            statement.setLong(1, id);

            try (ResultSet resultSet =
                         statement.executeQuery()) {
                return resultSet.next()
                        ? mapRow(resultSet)
                        : null;
            }
        }
    }

    public List<Student> findAll() throws SQLException {
        List<Student> students = new ArrayList<>();

        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(FIND_ALL_SQL);
             ResultSet resultSet = statement.executeQuery()) {

            while (resultSet.next()) {
                students.add(mapRow(resultSet));
            }
        }

        return students;
    }

    public boolean update(Student student) throws SQLException {
        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(UPDATE_SQL)) {

            bindStudent(statement, student);
            statement.setLong(4, student.getId());

            return statement.executeUpdate() == 1;
        }
    }

    public boolean delete(long id) throws SQLException {
        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(DELETE_SQL)) {

            statement.setLong(1, id);
            return statement.executeUpdate() == 1;
        }
    }

    public int[] batchInsert(List<Student> students)
            throws SQLException {
        if (students.isEmpty()) {
            return new int[0];
        }

        try (Connection connection =
                     DatabaseConfig.getConnection()) {
            connection.setAutoCommit(false);

            try {
                int[] updateCounts;

                try (PreparedStatement statement =
                             connection.prepareStatement(INSERT_SQL)) {
                    for (Student student : students) {
                        bindStudent(statement, student);
                        statement.addBatch();
                    }

                    updateCounts = statement.executeBatch();
                }

                connection.commit();
                return updateCounts;
            } catch (SQLException | RuntimeException e) {
                rollback(connection, e);
                throw e;
            }
        }
    }

    private static void bindStudent(
            PreparedStatement statement,
            Student student
    ) throws SQLException {
        statement.setString(1, student.getName());
        statement.setString(2, student.getEmail());
        statement.setInt(3, student.getAge());
    }

    private static Student mapRow(ResultSet resultSet)
            throws SQLException {
        return new Student(
                resultSet.getLong("id"),
                resultSet.getString("name"),
                resultSet.getString("email"),
                resultSet.getInt("age")
        );
    }

    private static void rollback(
            Connection connection,
            Throwable originalFailure
    ) {
        try {
            connection.rollback();
        } catch (SQLException rollbackFailure) {
            originalFailure.addSuppressed(rollbackFailure);
        }
    }
}
```

The batch method is explicitly transactional. It does not retrieve generated IDs; the single-row `create` method separately practices that concern.

### 27.7 Complete `AccountTransferService.java`

```java
package com.example.jdbc.service;

import com.example.jdbc.config.DatabaseConfig;

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class AccountTransferService {

    private static final String DEBIT_SQL = """
            UPDATE accounts
            SET balance = balance - ?
            WHERE id = ? AND balance >= ?
            """;

    private static final String CREDIT_SQL = """
            UPDATE accounts
            SET balance = balance + ?
            WHERE id = ?
            """;

    private static final String BALANCE_SQL =
            "SELECT balance FROM accounts WHERE id = ?";

    public void transfer(
            long fromId,
            long toId,
            BigDecimal amount
    ) throws SQLException {
        BigDecimal exactAmount =
                validateTransfer(fromId, toId, amount);

        try (Connection connection =
                     DatabaseConfig.getConnection()) {
            connection.setAutoCommit(false);

            try {
                try (PreparedStatement debit =
                             connection.prepareStatement(DEBIT_SQL);
                     PreparedStatement credit =
                             connection.prepareStatement(CREDIT_SQL)) {

                    debit.setBigDecimal(1, exactAmount);
                    debit.setLong(2, fromId);
                    debit.setBigDecimal(3, exactAmount);

                    if (debit.executeUpdate() != 1) {
                        throw new SQLException(
                                "Debit failed: source is missing "
                                        + "or balance is insufficient"
                        );
                    }

                    credit.setBigDecimal(1, exactAmount);
                    credit.setLong(2, toId);

                    if (credit.executeUpdate() != 1) {
                        throw new SQLException(
                                "Credit failed: destination account "
                                        + "is missing"
                        );
                    }
                }

                connection.commit();
            } catch (SQLException | RuntimeException e) {
                rollback(connection, e);
                throw e;
            }
        }
    }

    public BigDecimal findBalance(long accountId)
            throws SQLException {
        try (Connection connection =
                     DatabaseConfig.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(BALANCE_SQL)) {

            statement.setLong(1, accountId);

            try (ResultSet resultSet =
                         statement.executeQuery()) {
                return resultSet.next()
                        ? resultSet.getBigDecimal("balance")
                        : null;
            }
        }
    }

    private static BigDecimal validateTransfer(
            long fromId,
            long toId,
            BigDecimal amount
    ) {
        if (fromId <= 0 || toId <= 0) {
            throw new IllegalArgumentException(
                    "Account IDs must be positive"
            );
        }

        if (fromId == toId) {
            throw new IllegalArgumentException(
                    "Source and destination must differ"
            );
        }

        if (amount == null || amount.signum() <= 0) {
            throw new IllegalArgumentException(
                    "Amount must be positive"
            );
        }

        try {
            return amount.setScale(2, RoundingMode.UNNECESSARY);
        } catch (ArithmeticException e) {
            throw new IllegalArgumentException(
                    "Amount may have at most two decimal places",
                    e
            );
        }
    }

    private static void rollback(
            Connection connection,
            Throwable originalFailure
    ) {
        try {
            connection.rollback();
        } catch (SQLException rollbackFailure) {
            originalFailure.addSuppressed(rollbackFailure);
        }
    }
}
```

Because these are directly opened connections that close immediately, the methods do not need to restore auto-commit for reuse. A future pooled implementation must return connections with clean state, while still committing or rolling back before close.

### 27.8 Complete `Main.java`

```java
package com.example.jdbc;

import com.example.jdbc.config.DatabaseConfig;
import com.example.jdbc.dao.StudentDAO;
import com.example.jdbc.model.Student;
import com.example.jdbc.service.AccountTransferService;

import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.SQLException;
import java.util.List;
import java.util.Scanner;

public class Main {

    private final Scanner scanner = new Scanner(System.in);
    private final StudentDAO studentDAO = new StudentDAO();
    private final AccountTransferService transferService =
            new AccountTransferService();

    public static void main(String[] args) {
        if (!testConnection()) {
            return;
        }

        new Main().runMenu();
    }

    private static boolean testConnection() {
        try (Connection connection =
                     DatabaseConfig.getConnection()) {
            System.out.println("Connected successfully");
            return true;
        } catch (SQLException e) {
            printSqlException(e);
            return false;
        } catch (RuntimeException e) {
            System.err.println(
                    "Configuration error: " + e.getMessage()
            );
            return false;
        }
    }

    private void runMenu() {
        while (true) {
            printMenu();
            String choice = scanner.nextLine().trim();

            try {
                switch (choice) {
                    case "1" -> addStudent();
                    case "2" -> findStudent();
                    case "3" -> listStudents();
                    case "4" -> updateStudent();
                    case "5" -> deleteStudent();
                    case "6" -> batchInsert();
                    case "7" -> transferMoney();
                    case "0" -> {
                        return;
                    }
                    default ->
                            System.out.println("Unknown option.");
                }
            } catch (SQLException e) {
                printSqlException(e);
            } catch (IllegalArgumentException e) {
                System.err.println(
                        "Invalid input: " + e.getMessage()
                );
            }
        }
    }

    private void addStudent() throws SQLException {
        Student student = readStudentWithoutId();
        long id = studentDAO.create(student);
        System.out.println("Created student with ID " + id);
    }

    private void findStudent() throws SQLException {
        Student student =
                studentDAO.findById(readLong("ID: "));

        System.out.println(
                student == null
                        ? "Student not found."
                        : student
        );
    }

    private void listStudents() throws SQLException {
        List<Student> students = studentDAO.findAll();

        if (students.isEmpty()) {
            System.out.println("No students.");
            return;
        }

        students.forEach(System.out::println);
    }

    private void updateStudent() throws SQLException {
        long id = readLong("ID to update: ");
        Student student = readStudentWithoutId();
        student.setId(id);

        System.out.println(
                studentDAO.update(student)
                        ? "Updated."
                        : "Student not found."
        );
    }

    private void deleteStudent() throws SQLException {
        boolean deleted =
                studentDAO.delete(readLong("ID to delete: "));

        System.out.println(
                deleted ? "Deleted." : "Student not found."
        );
    }

    private void batchInsert() throws SQLException {
        long suffix = System.currentTimeMillis();

        List<Student> students = List.of(
                new Student(
                        "Batch A",
                        "batch.a." + suffix + "@example.com",
                        20
                ),
                new Student(
                        "Batch B",
                        "batch.b." + suffix + "@example.com",
                        21
                ),
                new Student(
                        "Batch C",
                        "batch.c." + suffix + "@example.com",
                        22
                ),
                new Student(
                        "Batch D",
                        "batch.d." + suffix + "@example.com",
                        23
                )
        );

        int[] counts = studentDAO.batchInsert(students);
        System.out.println(
                "Batch completed for "
                        + counts.length + " statements."
        );
    }

    private void transferMoney() throws SQLException {
        long from = readLong("From account ID: ");
        long to = readLong("To account ID: ");
        BigDecimal amount =
                new BigDecimal(readRequired("Amount: "));

        System.out.println(
                "Before: from="
                        + transferService.findBalance(from)
                        + ", to="
                        + transferService.findBalance(to)
        );

        transferService.transfer(from, to, amount);

        System.out.println("Committed.");
        System.out.println(
                "After: from="
                        + transferService.findBalance(from)
                        + ", to="
                        + transferService.findBalance(to)
        );
    }

    private Student readStudentWithoutId() {
        String name = readRequired("Name: ");
        String email = readRequired("Email: ");
        int age = Integer.parseInt(readRequired("Age: "));

        return new Student(name, email, age);
    }

    private long readLong(String prompt) {
        return Long.parseLong(readRequired(prompt));
    }

    private String readRequired(String prompt) {
        System.out.print(prompt);
        String value = scanner.nextLine().trim();

        if (value.isEmpty()) {
            throw new IllegalArgumentException(
                    "Value cannot be blank"
            );
        }

        return value;
    }

    private static void printSqlException(SQLException e) {
        for (SQLException current = e;
             current != null;
             current = current.getNextException()) {
            System.err.printf(
                    "Database error: %s | SQLState=%s | code=%d%n",
                    current.getMessage(),
                    current.getSQLState(),
                    current.getErrorCode()
            );
        }
    }

    private static void printMenu() {
        System.out.println("""

                === Student Management ===
                1. Add student
                2. Find student by ID
                3. List students
                4. Update student
                5. Delete student
                6. Batch insert sample students
                7. Transfer money (transaction exercise)
                0. Exit
                """);

        System.out.print("Choose: ");
    }
}
```

This is a thin JAR, and the POM does not configure a `Main-Class` manifest. The exercise intentionally runs through Maven/IDE so the main class and pgJDBC runtime classpath are supplied correctly; a plain `java -jar` launch would lack both configurations.

Normal lifecycle choices:

```bash
docker compose stop
docker compose start
docker compose down
```

`stop`/`start` keep the existing container. `down` removes the container and
network but keeps the named volume; use `up -d` to recreate the container later.

```bash
docker compose down -v
```

> ⚠ **Destructive — practice project only:** The `-v` form also deletes the
> database volume. A later `up -d` recreates the user/database, but you must rerun
> section 27.1's table and seed SQL.

### Final architecture

```text
Main / DAO / service (host Java process)
        ↓
PreparedStatement + JDBC Connection
        ↓
PostgreSQL JDBC driver (pgJDBC)
        ↓
jdbc:postgresql://localhost:5432/jdbc_practice
        ↓
host port 5432
        ↓ Docker mapping 5432:5432
PostgreSQL container port 5432
        ↓
jdbc_practice database
```

Reading data:

```text
PostgreSQL container
    ↓
ResultSet
    ↓
StudentDAO.mapRow
    ↓
Student object
    ↓
Main
```

Atomic transfer:

```text
one Connection with auto-commit disabled
       ├── debit affects exactly one row
       ├── credit affects exactly one row
       └── both succeed → commit
                any failure → rollback
```

Final outcome to explain and implement yourself:

```text
Docker + Compose available
        ↓
compose.yaml starts PostgreSQL
        ↓
named volume stores database files
        ↓
tables created manually through in-container psql
        ↓
Java Maven application on host
        ↓
java.sql API
        ↓
pgJDBC
        ↓
localhost:5432
        ↓
Docker port mapping
        ↓
PostgreSQL container
        ↓
jdbc_practice database
        ↓
students / accounts
        ↓
CRUD + generated keys + batch + atomic transaction
        ↓
working JDBC + PostgreSQL console application
```

If you can rebuild the application from that flow without copying section 27, you are ready to use plain JDBC correctly in normal Java projects and to understand what future frameworks automate.
