# Backtracking — Essential Concepts (Java 21)

Backtracking explores a decision, learns what follows from it, and returns to a state from which another decision can be tried. The central skill is defining what a partial solution means and proving that each branch preserves that meaning.

### Code and counting conventions

All Java fences are members of one scratch class **BacktrackingExamples**, with `import java.util.*;` at file scope. Combine them in document order. There are no external dependencies or preview features. Examples are single-threaded and assume feasible allocations.

Public wrappers reject null required inputs with NullPointerException. Explicitly checked invalid numeric/domain values throw IllegalArgumentException. Stated small size bounds and distinctness requirements labelled **preconditions** are trusted. Internal helpers receive valid state from their wrappers and do not repeat validation.

Each example states its character/numeric domain, duplicate semantics, output order, and mutation policy. Enumeration sizes are deliberately small: basic subsets/combinations use at most 12 elements, permutations at most 8. These are teaching limits, not promises that arbitrary exponential output is feasible. Unless a local restriction says otherwise, int values may be negative, zero, or endpoints. Comparisons use ordinary relations rather than overflow-prone subtraction.

A public invocation owns fresh working state and fresh returned containers. Inputs are read-only except an explicitly documented temporary board-marking variant, which restores contents before returning. Saved list snapshots are shallow copies of immutable Integer references. Returned lists are mutable unless explicitly stated otherwise; they must not alias the working path or one another.

Use these quantities consistently:

| Symbol | Meaning |
| --- | --- |
| n | Input element count |
| b | Maximum branching factor under the stated search model |
| d | Maximum number of chosen decisions along a branch |
| V | Actual recursive helper invocations, including bases and rejected calls when relevant |
| D | Maximum simultaneously live helper invocations, including the root/base |
| B | Number of emitted results |
| S | Sum of lengths of emitted results |
| L | Target word length in UTF-16 code units; board examples restrict characters to a..z |
| R, C | Rectangular board row/column counts |

A path of d call edges has d+1 frames in that recursive family. A public wrapper adds a constant number of frames. Auxiliary space excludes existing input and required output but includes recursion, paths, visited structures, sorted copies, and library workspace. Total output storage includes the B containers as well as their S elements.

## 2. Recursion, DFS, and backtracking

Imagine reaching a junction in a maze. You choose one passage, follow it until you finish or discover that it cannot work, return to the junction, and try another passage. A note describing your current route must lose the passage you just abandoned. Otherwise the next attempt would begin with the wrong history.

That analogy captures **branch exploration and restoration**, but the exact visited rule depends on the task. Finding whether an ordinary maze cell is reachable may safely mark cells permanently. Enumerating simple routes, where cells may be used in different routes, requires path-local restrictions. “Maze” alone does not specify an algorithm.

| Concept | What it describes | Small example | State implication |
| --- | --- | --- | --- |
| Recursion | A method invokes itself on a smaller/different instance with a precise promise | Sum a suffix, combine two subtree heights | No search alternatives or undo are inherently required |
| DFS | Explore one branch deeply before siblings | Visit every stored tree node in preorder | May use recursion or an explicit stack; permanent visited can suit reachability |
| Backtracking | Systematically explore choices while managing the partial solution and constraints between alternatives | Enumerate arrangements, select compatible items, spell a path | Shared working state must be restored or isolated before alternatives |
| Iterative backtracking | The same search with explicit frames/continuation state | Stack records choice index and restoration stage | The call stack is replaced; pending undo still has to be represented |

A recursive sum makes one smaller call and combines a number. It is recursion without backtracking. A stored-tree preorder DFS may simply read nodes; there is no modified candidate to undo. A permutation search often uses recursive DFS because each recursive level chooses the next output position, then returns to try another.

DFS is an **exploration order**, while backtracking supplies a **choice/constraint model and state discipline**. The terms overlap in practice; neither should be used to conceal the state contract.

### Explicit undo is one way to isolate sibling state

If children share one mutable path, add → recurse → remove makes sibling calls see the correct prefix. A different implementation may pass a new list or immutable string to each child. It then has no shared path mutation to undo, but it pays for construction/copies. Primitive parameters such as index or remaining target are copied values and normally need no undo assignment.

An explicit stack can hold frame fields such as next candidate, chosen index, and whether a child has returned. To reproduce recursive behavior, it must distinguish “before exploration” from “after child completion,” where restoration happens. Simply pushing all candidate values without their pending work is not a general translation.

## 3. Implicit decision trees

Suppose the input positions contain [1,2,3] and the question is which positions to select. At index i, decide whether the current element belongs in the result. State (i,path) means every earlier position has been decided and path contains exactly those earlier values that were included.

Explore **include first**, then exclude. The following diagram shows the complete tree; I and E label include/exclude of the element being decided.

```text
                                  (0,[])
                       I 1 /                    \ E 1
                        (1,[1])                 (1,[])
                  I 2 /       \ E 2        I 2 /       \ E 2
                (2,[1,2])    (2,[1])       (2,[2])     (2,[])
              I3 /  \ E3   I3 / \ E3     I3 / \ E3   I3 / \ E3
            [1,2,3] [1,2] [1,3] [1]     [2,3] [2]    [3]   []
                       all leaves have i=3
```

The root has made no decisions. An edge fixes one input position. Depth i counts decided positions; leaves at depth n have no undecided positions. Here every leaf is a valid subset, including the empty subset.

There are 1,2,4,8 states at successive depths: **15 helper invocations**, **8 outputs**, and at most **4 live helper frames**. The eight branches do not remain on the stack simultaneously; after one finishes, the call resumes its sibling exploration.

| Tree feature | Meaning in this search |
| --- | --- |
| Node | A specific decision prefix, not merely a path’s current numeric sum |
| Edge | Include or exclude the next position |
| Branching factor | Exactly 2 at every non-leaf |
| Depth | Number of positions decided, 0..n |
| Complete candidate | Every position decided |
| Invalid partial state | None in unrestricted subset selection |
| Pruned branch | None here; a later constraint could justify eliminating some subtrees |

This is an **implicit tree**. Code constructs child states as needed instead of allocating an object for every tree node. The explored recursion tree is not the input array or a binary search tree.

### A constraint changes which nodes may be explored

If only subsets of exactly two positions are required, a prefix with three selected positions cannot finish legally. A prefix at index 2 containing no selections has only one position left and also cannot finish. These are different impossibility arguments: too many already selected versus too few available.

A complete valid solution is not an invalid branch. Stopping after saving one leaf is completion; rejecting an incomplete state because no extension can succeed is pruning. Duplicate sibling suppression is a further form of reducing equivalent search, whose proof establishes that a canonical representative remains.

Do not automatically apply a “two branches means 2^n” claim to every method. Permutations have a shrinking set of choices, reusable sum searches have numeric depth, and boards have geometry plus path restrictions.

## 4. Designing the search state

Start with the question **“What does one call promise to explore?”** Then choose parameters that make that promise expressible. A method named backtrack with three unexplained ints has not defined its state.

For a subset helper, a useful promise is:

> Given decisions for positions before i and a path containing exactly their included values, append every completion using positions i..n-1 to output; return with path exactly as it was on entry.

That promise includes **output effects and restoration**, not just a mathematical return value.

### Eight questions before implementation

1. What is already fixed in the partial solution?
2. Which choices are currently eligible?
3. Which constraints make a choice invalid?
4. What condition identifies a complete solution?
5. How is a complete result represented and saved?
6. Which parameters describe what remains?
7. Which objects are shared across calls?
8. Which exact state must equal its entry value when this call returns?

| State representation | Useful meaning | Why it fits | What must be restored |
| --- | --- | --- | --- |
| int index | First undecided input position | Every position is considered in a fixed order | Nothing for the primitive parameter |
| int start | Smallest eligible next candidate index | Canonical order avoids order-equivalent combinations | Nothing for the primitive parameter |
| List<Integer> path | Chosen prefix in order | It can be extended at the end and copied at completion | Previous contents/length |
| boolean[] used | Which input positions occur in the current arrangement | Any unused position can fill the next output slot | Chosen position’s previous mark |
| HashSet<Integer> | Membership of chosen position IDs, or values already tried at one depth | Useful when the domain is sparse or grouping equal values | Remove path-local insertions; a depth-local set naturally expires |
| int remaining | Amount still needed under a stated sum model | A positive choice can shrink a nonnegative target | Primitive child values are copied |
| row, column, character index | Current board coordinate and next/current matched character | Geometry and target progress are explicit | Associated visited mark or board value |
| StringBuilder | Text of the chosen pieces | Supports multi-character additions without repeatedly copying prefixes | Saved earlier length, when the earlier prefix itself was not edited |

A set of **values** cannot replace used positions when equal values represent separate available occurrences. With [4,4,7], two input positions hold 4; selecting one must not prohibit selecting the other at a later position if the output contract permits [4,4,...]. A set of positions or boolean[] models that supply correctly. A per-depth set of tried values can instead suppress equivalent **sibling** choices.

### Path state, output, and immutable input have different jobs

```text
input a                     shared, read-only facts
       \
call (index/start, ...) ---> path / used / visited    temporary working state
       \                         |
        \----------------------> output              accumulated snapshots
```

All active calls may reference the same path and output. They intentionally append to one output collection and do not undo already emitted solutions. They temporarily modify one path and do undo its branch-specific edits.

“Global output” sometimes means shared across one invocation’s search. It need not mean a static field shared across every public call. Prefer invocation-owned objects when no persistence is requested.

## 5. Choose, explore, and undo

The sequence is a conceptual pattern, not a template to paste into every search:

```text
entry state P
     |
 choose x        -> P with x appended / marked
     |
 explore child  -> all legal completions of that choice
     |
 undo x          -> exactly P again
     |
 try sibling y  -> P with y appended / marked
```

Suppose a current path is [4]. The next alternatives are 9 and 6.

| Stage | Shared path contents | What is established |
| --- | --- | --- |
| Enter current call | [4] | Ancestor prefix is fixed |
| Choose 9 | [4,9] | Child may use this extended prefix |
| Child returns | [4,9] | Child restored its own deeper edits |
| Undo current choice | [4] | Current call restores its entry prefix |
| Choose 6 | [4,6] | Sibling starts from the same ancestor state |
| Child returns, undo | [4] | Current call may now return safely |

Notice the two restoration responsibilities: the child removes its deeper choices, and the caller removes the choice it made before entering that child. If both remove the caller’s element, too much is undone; if neither does, the sibling inherits a stale choice.

The following runnable demonstration isolates that lifecycle. It records two simulated child observations and the restored final state; the full recursive example follows in Section 7.

```java
static List<List<Integer>> restorationDemo() {
    List<Integer> path = new ArrayList<>(List.of(4));
    List<List<Integer>> observations = new ArrayList<>();
    for (int candidate : new int[]{9, 6}) {
        path.add(candidate);                         // choose
        observations.add(new ArrayList<>(path));    // observe child state
        path.remove(path.size() - 1);               // undo
    }
    observations.add(new ArrayList<>(path));
    return observations;
}
```

Result: [[4,9],[4,6],[4]]. Replacing the final removal with “do nothing” would make the second observed path [4,9,6], representing a different decision history.

### Why removing the last element is the correct inverse

ArrayList<Integer> has both remove(int index) and remove(Object value). The expression path.size()-1 has primitive type int, so it removes the element at the final **index**. The element’s numeric value is irrelevant.

If the path is [9,4,9], undoing the last addition should produce [9,4]. Removing Integer.valueOf(9) instead removes the **first equal occurrence**, producing [4,9]. The path no longer represents the ancestor prefix. Removing by value also scans; removing the known final index has no tail to shift.

### Return paths and restoration

A loop that always executes its undo after the child returns is enough for ordinary enumeration with normal returns. A boolean search may return immediately on success. If that bypasses the undo statement, caller-visible state can remain changed.

One approach computes the child’s boolean, restores state, then returns if true. Another uses try/finally around exploration. finally executes even when the try block returns. The board examples use this to make successful and failed paths share the same cleanup rule. It does not make arbitrary failures such as an exhausted runtime stack a general transactional guarantee; the educational contracts describe ordinary completed calls with sufficient resources.

## 6. Java references, snapshots, and buffers

### 6.1 A new frame is not a new list

Each recursive invocation has local parameter variables. Passing an ArrayList copies its reference value, so those local variables can still identify **one shared mutable object**. Reassigning a local parameter to a different list does not reassign the caller’s variable; adding/removing through that parameter changes the shared object.

A result container also stores reference values. result.add(path) does not freeze the current contents. It saves another reference to path.

```java
static List<List<Integer>> aliasingWitness() {
    List<Integer> path = new ArrayList<>();
    List<List<Integer>> result = new ArrayList<>();
    path.add(4);
    result.add(path);                    // deliberately wrong snapshot policy
    path.add(9);
    result.add(path);
    path.clear();
    return result;
}

static List<List<Integer>> snapshotDemo() {
    List<Integer> path = new ArrayList<>();
    List<List<Integer>> result = new ArrayList<>();
    path.add(4);
    result.add(new ArrayList<>(path));
    path.add(9);
    result.add(new ArrayList<>(path));
    path.clear();
    return result;
}
```

aliasingWitness returns [[],[]], and its two entries identify the **same list**. snapshotDemo returns [[4],[4,9]], with distinct saved containers.

```text
Wrong:
result[0] ----+
result[1] ----+----> working list P, now []
path --------+

Snapshots:
path -------------> working list P, now []
result[0] --------> saved list A [4]
result[1] --------> saved list B [4,9]
```

A snapshot copies the list’s element references. Here Integer objects are immutable, so this suffices. With mutable nodes or arrays as elements, later edits inside an element can still affect all shallow copies. Decide whether logical results need immutable elements, deeper copies, or identities deliberately shared by the contract. [ArrayList copy/removal API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/ArrayList.html)

Restoration and copying solve different problems. Copying protects a saved answer from later work. Undo protects a sibling’s starting state. Doing only one does not generally supply the other.

### 6.2 Restore a text buffer to a saved length

Appending a whole token may add several characters. “Remove one character afterward” is not the inverse. Save the old length and restore it after the child returns. This works because the child appends to the tail and restores its own edits; it does not rewrite characters in the earlier prefix.

Original example: select one string from each position’s options and concatenate them. Rows are choice positions. Duplicate strings and empty strings are legal, and different choice-index paths may intentionally produce equal output text.

**Contract:** options and every row/token are nonnull; at most 8 rows, at most 4 choices per row, and at most 8 UTF-16 code units per token are preconditions. Return a fresh list in row-option DFS order. Zero rows produce [""], because there is one empty sequence of decisions. An empty row produces no complete outputs. Input containers/strings are unchanged. Validate all required references before exploring.

```java
static List<String> optionTexts(String[][] options) {
    Objects.requireNonNull(options, "options");
    for (String[] row : options) {
        Objects.requireNonNull(row, "row");
        for (String token : row) {
            Objects.requireNonNull(token, "token");
        }
    }
    List<String> result = new ArrayList<>();
    textFrom(options, 0, new StringBuilder(), result);
    return result;
}

private static void textFrom(String[][] options, int position,
                             StringBuilder text, List<String> result) {
    if (position == options.length) {
        result.add(text.toString());
        return;
    }
    for (String token : options[position]) {
        int oldLength = text.length();
        text.append(token);
        try {
            textFrom(options, position + 1, text, result);
        } finally {
            text.setLength(oldLength);
        }
    }
}
```

| Input / event | Expected state or output |
| --- | --- |
| options=[["ab","x"],["Q",""]] | ["abQ","ab","xQ","x"] |
| Start text="" then choose "ab" | text="ab"; saved oldLength=0 |
| Choose "Q" in the child | text="abQ"; that child’s saved oldLength=2 |
| Undo "Q" | text="ab" |
| Choose "" then undo it | text remains "ab" |
| Undo "ab" | text="" |
| options=[] | [""] |
| options=[[]] | [] |
| options=[["a","a"]] | ["a","a"]; two choice paths, equal text |
| options=[["ok"],[null]] | NPE before search begins |

The recursive contract says text equals the concatenation of choices before position and is restored on return. Each recursive edge advances position, even when token is empty, so empty tokens do not prevent termination.

StringBuilder.toString creates an immutable string result. Later truncating the working builder does not rewrite that string. setLength with a **larger** length fills new positions with NUL characters; it does not recover deleted characters. Saving length only restores tail additions, not arbitrary edits to earlier content. [StringBuilder API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/StringBuilder.html)

If P is the number of validated option entries, V the calls, A the total characters appended across explored edges, and S the total output text length, a useful time account is O(P+V+A+S+1), with amortized builder growth. Maximum live text length M and depth d give O(M+d+1) working space, plus O(B+S) output. Allocating a different growing string per child changes copying costs.

## 7. Subsets through include and exclude

A subset records which input positions are included; their order in the input supplies a canonical output order. With distinct values, every include/exclude bit vector corresponds to a different value subset.

Original running example: values [4,9]. At each index decide include first, then exclude. The array’s order is preserved within a returned subset. A subset’s **membership** is not ordered, but fixing a representation prevents equivalent reorderings such as [9,4] from being generated separately.

**Contract:** nonnull int[]; n<=12 and all values distinct are preconditions. Negative/zero/extreme ints are legal. Return fresh outer/inner lists, input unchanged, include-first DFS order. Empty input returns [[]]. Integer values are copied as references to immutable boxed values; no arithmetic on them is needed.

### Derive the recursive promise

Before subsetFrom(a,i,path,result), positions below i have been decided. path lists exactly the included values among those positions in original order.

- If i==n, no choices remain; path is a complete result.
- Otherwise include a[i], delegate the remaining suffix, and remove that inclusion.
- Then delegate the same suffix without a[i].
- Each call returns with path equal to its entry state.

```java
static List<List<Integer>> selections(int[] values) {
    Objects.requireNonNull(values, "values");
    List<List<Integer>> result = new ArrayList<>();
    subsetFrom(values, 0, new ArrayList<>(), result);
    return result;
}

private static void subsetFrom(int[] a, int i, List<Integer> path,
                               List<List<Integer>> result) {
    if (i == a.length) {
        result.add(new ArrayList<>(path));
        return;
    }
    path.add(a[i]);
    subsetFrom(a, i + 1, path, result);
    path.remove(path.size() - 1);
    subsetFrom(a, i + 1, path, result);
}
```

### Complete small traversal

The table records movements and output events; a leaf row includes entering that base call and returning from it. “Output” lists only the new snapshot, not the shared working path.

| Step | i / depth | Working path | Action | Undo / restored state | New output |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | [] | Enter root | — | — |
| 2 | 0 | [4] | Include position 0 | Pending removal of 4 | — |
| 3 | 1 | [4] | Enter suffix | — | — |
| 4 | 1 | [4,9] | Include position 1 | Pending removal of 9 | — |
| 5 | 2 | [4,9] | Complete leaf | Child returns [4,9] unchanged | [4,9] |
| 6 | 1 | [4] | Remove chosen 9 | Prefix [4] restored | — |
| 7 | 2 | [4] | Exclude 9; complete leaf | Return [4] unchanged | [4] |
| 8 | 0 | [] | First suffix done; remove 4 | Root prefix [] restored | — |
| 9 | 1 | [] | Exclude 4; enter suffix | — | — |
| 10 | 1 | [9] | Include position 1 | Pending removal of 9 | — |
| 11 | 2 | [9] | Complete leaf | Child returns [9] unchanged | [9] |
| 12 | 1 | [] | Remove 9 | Prefix [] restored | — |
| 13 | 2 | [] | Exclude 9; complete leaf | Return [] unchanged | [] |
| 14 | 0 | [] | Return root | Entry state restored | — |

| Input | Exact output order |
| --- | --- |
| [4,9] | [[4,9],[4],[9],[]] |
| [2,5,8] | [[2,5,8],[2,5],[2,8],[2],[5,8],[5],[8],[]] |
| [] | [[]] |
| [0] | [[0],[]] |
| [MIN,MAX] | [[MIN,MAX],[MIN],[MAX],[]] |

Passing duplicate input would violate this example’s distinctness precondition: positions would still be enumerated, but equal-valued subsets could be repeated. Section 11 supplies the changed uniqueness policy.

### Correctness and costs

**Soundness:** a value is appended only when its position is included; index progression prevents using a position twice. At a base every position is decided.

**Completeness:** take any requested subset and follow include exactly at its selected positions, exclude elsewhere. The method explores that unique root-to-leaf route.

**Uniqueness:** two different decision bit vectors differ at some position. With distinct input values, they therefore represent different subsets. This proof depends on distinctness.

**Restoration and termination:** the include child restores its deeper edits; the caller removes its own one addition. The exclude child makes no caller-level addition. Every child increases i, decreasing n-i.

There are B=2^n results and V=2^(n+1)-1 calls. For n>=1, each value occurs in half of the results, so S=n*2^(n-1) element references are copied into output. Traversal alone is Θ(2^n); **materializing copied subsets is Θ((n+1)*2^n)**, usually written O(n*2^n) for n>=1.

Working path, capacity, and stack are O(n+1), not O(2^n). Required output is Θ(B+S). For n=0 there is still one call and one empty result container. Returning only a count would have a different output contract and might avoid enumeration entirely.

## 8. Permutations through unused positions

A permutation fills **ordered output positions**. For three distinct values, selecting 4 then 7 differs from selecting 7 then 4. A start index that forbids returning to smaller input indexes would omit legitimate arrangements.

At each output position, choose any unused **input position**. used[i] tells whether that occurrence is already in the current path. It is path-local state shared for efficiency, not a permanent statement that the value has ever appeared in any result.

**Contract:** nonnull int[]; n<=8 and distinct values are preconditions. Any ints are legal; input unchanged. Return full-length arrangements in DFS order, scanning input indexes ascending at each level. Empty input has one empty arrangement, [[]]. Every result is a fresh list.

```java
static List<List<Integer>> arrangements(int[] values) {
    Objects.requireNonNull(values, "values");
    List<List<Integer>> result = new ArrayList<>();
    arrangeFrom(values, new boolean[values.length],
                new ArrayList<>(), result);
    return result;
}

private static void arrangeFrom(int[] a, boolean[] used,
                                List<Integer> path,
                                List<List<Integer>> result) {
    if (path.size() == a.length) {
        result.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) {
            continue;
        }
        used[i] = true;
        path.add(a[i]);
        arrangeFrom(a, used, path, result);
        path.remove(path.size() - 1);
        used[i] = false;
    }
}
```

The helper invariant is stronger than “used has some true entries”: path contains each marked input position exactly once, in choice order, and contains no unmarked position. On return both path and used equal their entry state.

### Decision tree and selected return events

```text
             |     |     |     |     |     |
```

### Correctness and costs

Every result has n positions filled by n distinct input occurrences, so it is a valid permutation. For any desired ordering, its first occurrence is eligible at the root, its second remains eligible in that child, and so on; therefore every permutation is reached. Distinct occurrence orders give distinct value sequences under the distinctness precondition.

Each choice marks one unused position; its child restores deeper marks, then the caller removes the path value and clears exactly its own mark. The count of unused positions decreases, so depth is n decisions and maximum helper frames n+1.

The leaf count is n!. At depth j the number of states is P(n,j)=n!/(n-j)!. Thus V=sum(j=0..n)P(n,j), which is O(n!+1). For n=3, the levels contain 1,3,6,6 states: 16 calls, six outputs, four live frames maximum.

This implementation scans n candidate indexes at every non-base state, including already used ones. Together with n-element snapshots, total time is **O(n*n!+1)**, and O(n+1) auxiliary space holds used, the path, and stack. Output stores Θ((n+1)*n!) references/containers. An implementation with a different choice representation may change internal scanning work, but it cannot materialize all n-length results for less than their output size.

## 9. Fixed-size combinations

A combination selects k input positions while ignoring selection order. With values [2,5,8,11], selecting 2 and 8 is the same membership choice as selecting 8 and 2. Generate only increasing input-index sequences, so each membership set has one canonical route.

For n distinct single-use values, compare the output contracts before choosing the recursion:

| Object being generated | Is order part of answer identity? | Chosen size | Number of results |
| --- | --- | --- | --- |
| Subset | No; use a canonical representation | Any size 0..n | 2^n |
| Size-k combination | No | Exactly k | binomial(n,k) |
| Full permutation | Yes | All n occurrences | n! |

All three have one empty object in their appropriate empty case. Reuse or duplicate-value identification changes these counting assumptions and must be modeled separately.

A start index is a **choice eligibility boundary**: every index below start is no longer eligible in this branch. It is not the count of elements already chosen; path.size() supplies that count.

**Contract:** nonnull array, n<=12 and distinct values are preconditions; validate 0<=k<=n. Full int values allowed. Input unchanged. Return k-element groups in lexicographic input-index order, not necessarily numeric order if input is unsorted. k=0 returns [[]]; k=n returns one group containing all values. Negative/out-of-range k throws IAE.

```java
static List<List<Integer>> groups(int[] values, int k) {
    Objects.requireNonNull(values, "values");
    if (k < 0 || k > values.length) {
        throw new IllegalArgumentException("k outside 0..n");
    }
    List<List<Integer>> result = new ArrayList<>();
    groupFrom(values, k, 0, new ArrayList<>(), result);
    return result;
}

private static void groupFrom(int[] a, int k, int start,
                              List<Integer> path,
                              List<List<Integer>> result) {
    if (path.size() == k) {
        result.add(new ArrayList<>(path));
        return;
    }
    int needed = k - path.size();
    for (int j = start; j <= a.length - needed; j++) {
        path.add(a[j]);
        groupFrom(a, k, j + 1, path, result);
        path.remove(path.size() - 1);
    }
}
```

Why stop at a.length-needed? If j is chosen, there must still be needed-1 positions after j. There are n-1-j such positions, so n-1-j>=needed-1, equivalently j<=n-needed. This pruning follows a count proof, independent of values.

| Prefix state | needed | Eligible next indexes | Produced groups below it |
| --- | --- | --- | --- |
| [], start=0, k=2 | 2 | 0,1,2 | All six groups |
| [2], start=1 | 1 | 1,2,3 | [2,5], [2,8], [2,11] |
| [5], start=2 | 1 | 2,3 | [5,8], [5,11] |
| [8], start=3 | 1 | 3 | [8,11] |
| Hypothetical [11], start=4 | 1 | None | Cannot complete; root never chooses it |

The full output is [[2,5],[2,8],[2,11],[5,8],[5,11],[8,11]]. For input [9,2,7], k=2, output is [[9,2],[9,7],[2,7]], preserving input-index order. It is not required to numerically sort members.

| Technique | What it restricts | Suitable when | Risk if substituted blindly |
| --- | --- | --- | --- |
| Increasing start index | Next chosen index cannot precede the prior one | Order-insensitive selection | Misses permutations such as [5,2] |
| used[] | A previously chosen occurrence cannot be chosen again | Order-sensitive arrangements | Generates several orders of one combination |
| Fixed include/exclude index | Decide every input occurrence once | Subsets and take/skip constraints | Does not directly express arbitrary next-position order |
| Path-local value set | Exclude currently selected values | Only if the contract forbids repeating a value | Can lose valid equal-valued occurrences |

Every generated path has increasing indexes and length k: soundness and uniqueness follow. Every k-position set has one increasing sequence; the loop considers it and the availability bound cannot remove it: completeness. Children advance start and add one value, so termination follows either increasing indexes or decreasing needed. Each caller removes its one appended value.

Let B=binomial(n,k), S=k*B, and V be the actual prefix states under the capacity pruning. Candidate-loop iterations correspond to child edges here, so time is O(V+S+1). Every explored prefix can extend to a leaf; charging its depth to leaf paths gives V<=1+k*B. Thus O((k+1)*B+1) is a useful output-sensitive bound. Working space is O(k+1), excluding output. For k=0 one empty result still takes O(1) work; for k=n a single chain takes O(n+1), not exponential work.

## 10. Reusable and single-use target choices

A target-combination search adds a remaining amount to the state. Its rules must answer two separate questions:

1. Does changing the order of chosen values create a different answer?
2. May a candidate be selected again after it has been chosen?

This section keeps order-insensitive groups in sorted numeric order and contrasts reuse directly. The example also caps the number of selected items, making it a small original planning model rather than a platform-specific Solution class.

### 10.1 One contract, two supply policies

**Contract:** candidates is nonnull, length<=10 is a precondition. Values must be positive and distinct; preparePositive validates those conditions on a sorted copy. Validate target in 0..30 and maxPicks in 0..10. reusable chooses unlimited supply subject to maxPicks, or at most one occurrence of each candidate. Return all valid value combinations, each nondecreasing, in ascending-choice DFS order. Input unchanged.

Target zero has one empty combination, [[]], including when maxPicks=0. A positive target with maxPicks=0 has no results. Validation still occurs before the zero-target answer, so candidate 0 is rejected even when target=0. Positivity is a checked part of the domain, not an unspoken assumption.

```java
private static int[] preparePositive(int[] candidates) {
    Objects.requireNonNull(candidates, "candidates");
    int[] sorted = candidates.clone();
    Arrays.sort(sorted);
    for (int i = 0; i < sorted.length; i++) {
        if (sorted[i] <= 0
                || (i > 0 && sorted[i] == sorted[i - 1])) {
            throw new IllegalArgumentException("positive distinct values required");
        }
    }
    return sorted;
}

static List<List<Integer>> sumBundles(int[] candidates, int target,
                                     int maxPicks, boolean reusable) {
    int[] a = preparePositive(candidates);
    if (target < 0 || target > 30 || maxPicks < 0 || maxPicks > 10) {
        throw new IllegalArgumentException("target or maxPicks out of range");
    }
    List<List<Integer>> result = new ArrayList<>();
    bundleFrom(a, 0, target, maxPicks, reusable,
               new ArrayList<>(), result);
    return result;
}

private static void bundleFrom(int[] a, int start, int remaining,
                               int maxPicks, boolean reusable,
                               List<Integer> path,
                               List<List<Integer>> result) {
    if (remaining == 0) {
        result.add(new ArrayList<>(path));
        return;
    }
    if (path.size() == maxPicks) {
        return;
    }
    for (int j = start; j < a.length; j++) {
        if (a[j] > remaining) {
            break;
        }
        path.add(a[j]);
        int nextStart = reusable ? j : j + 1;
        bundleFrom(a, nextStart, remaining - a[j], maxPicks,
                   reusable, path, result);
        path.remove(path.size() - 1);
    }
}
```

The helper promise relates **all** parameters: path is sorted, its sum plus remaining equals the original target, its size is at most maxPicks, and only candidates at/after start may be chosen next. It appends every completion that meets the supply rule and returns with path unchanged.

| Recursive next start | What remains eligible | Supply meaning |
| --- | --- | --- |
| j | The chosen candidate and all later values | Chosen value may be used again |
| j+1 | Only later candidates | This candidate is single-use |
| 0 regardless of choice | Earlier candidates become eligible again | May generate order-equivalent sequences, e.g. [3,8] and [8,3] |
| start+1 regardless of j | Not necessarily just the chosen position | Can mishandle both reuse and skipped candidate indexes |

### 10.3 Why the rules work, and what they cost

Positivity ensures a chosen value cannot increase remaining and cannot create an overshoot when the guard passes. Because a is sorted, a[j]>remaining implies every later candidate also exceeds remaining; none can complete a positive-only suffix. If a zero remainder is reached, a nonempty further choice would make the sum too large, so returning immediately loses no valid longer completion under this contract.

Sorted nondecreasing index sequences give each value multiset one canonical representation. Reuse at j supplies repeated copies of the same value without generating its reordered versions; advancing to j+1 prevents using a single-use candidate twice. All permitted canonical choices remain in the loop, establishing completeness. Path removals restore state, and depth increases toward maxPicks. Positivity additionally gives a numerical depth bound.

Let q be the minimum positive candidate when one exists. The maximum choices d are at most min(maxPicks,floor(target/q)) for reuse, and also at most n for single-use. With no candidates, the root decides directly. Count the actual V and S first: after sorting, loop work here is O(V+1), because each successful iteration creates one child and each loop has at most one failing break. Total time is O(n log(n+1)+V+S+1); O(n+d+1) auxiliary includes the sorted copy and the iterative library sort’s workspace within an O(n) allowance, path, and recursion. Output takes O(B+S).

A conservative n-branch depth-d bound for n>=2 gives V=O(n^d), then S<=d*B and total enumeration O(n^d*(d+1)). For n=1 the tree is a chain O(d+1), not a constant derived from 1^d. Pruning may reduce actual work; it does not justify assigning every target-combination search the same complexity.

## 11. Duplicate-aware enumeration

### 11.1 Positions, values, and logical answers

With [1,2,2], positions 1 and 2 are different occurrences. If subset outputs are identified only by their **value multiplicities**, selecting either one occurrence of 2 produces the same [2] answer. Selecting both produces [2,2], which is a different valid answer.

Therefore neither “treat all indexes as different answers” nor “remove every repeated value from the input” implements the required contract. The search must keep multiplicity while suppressing equivalent routes.

Sort a **copy** to group equal candidates. At a loop with eligibility start, skip an equal value only when it repeats an earlier candidate at the **same choice depth**:

`i>start && a[i]==a[i-1]`

If i==start, the candidate is the first eligible occurrence at that call. It may be equal to a value selected by an ancestor, and it remains legal when another occurrence is available.

### 11.2 Unique value subsets

**Contract:** nonnull int[], n<=12 precondition; full int values, including duplicates. Return each distinct value-multiset subset exactly once, members nondecreasing, prefix-first ascending-choice DFS order. The empty result is emitted first; empty input gives [[]]. Input unchanged, every saved path a fresh container.

```java
static List<List<Integer>> uniqueSelections(int[] values) {
    Objects.requireNonNull(values, "values");
    int[] a = values.clone();
    Arrays.sort(a);
    List<List<Integer>> result = new ArrayList<>();
    uniqueSubsetFrom(a, 0, new ArrayList<>(), result);
    return result;
}

private static void uniqueSubsetFrom(int[] a, int start,
                                     List<Integer> path,
                                     List<List<Integer>> result) {
    result.add(new ArrayList<>(path));
    for (int i = start; i < a.length; i++) {
        if (i > start && a[i] == a[i - 1]) {
            continue;
        }
        path.add(a[i]);
        uniqueSubsetFrom(a, i + 1, path, result);
        path.remove(path.size() - 1);
    }
}
```

This is a **prefix-output search**: every call’s current path is itself a valid subset, so emit at every entry. The include/exclude implementation instead emits only at its leaves. Moving a base case between these algorithms without changing its meaning can omit or duplicate results.

```text
Sorted positions: 0:1, 1:2, 2:2

                         []  emit
                  /1        |2(index 1)     X 2(index 2)
                [1]         [2]             same-depth duplicate
            /2(index 1)      |2(index 2)
          [1,2]             [2,2]
             |2(index 2)
          [1,2,2]
      At [1], choosing index 2 as its first 2 sibling is skipped.
      After choosing index 1, its child MAY choose index 2.
```

| Event in DFS order | start | Working prefix | Decision / output |
| --- | --- | --- | --- |
| Root entry | 0 | [] | Emit [] |
| Choose index 0 | 1 | [1] | Emit [1] |
| Choose index 1 | 2 | [1,2] | Emit [1,2] |
| Choose index 2 | 3 | [1,2,2] | Emit [1,2,2]; return and undo |
| Back at [1] | 1 | [1] | Skip index 2: equal sibling of index 1 |
| Back at root, choose index 1 | 2 | [2] | Emit [2] |
| Choose index 2 | 3 | [2,2] | Emit [2,2]; return and undo |
| Back at root | 0 | [] | Skip index 2; finish |

Output is [[],[1],[1,2],[1,2,2],[2],[2,2]]. There are six helper calls, seven candidate-loop iterations, two duplicate skips, and nine copied output elements. An input [2,2] still produces [[],[2],[2,2]].

Why is sibling suppression safe? The branch beginning with a later equal candidate cannot create a value-multiset completion unavailable to the earlier equal branch. Keeping the earlier occurrence leaves at least as much equal-value supply available later. The earlier branch represents all those logical results. Repeating that argument at each depth gives a canonical route. Along one branch, multiple equal occurrences remain available through advancing indexes.

For multiplicities f1,...,ft, the number of unique value subsets is B=product(fi+1). The search emits one per call, so V=B. Candidate loops may also inspect skipped siblings; a safe bound is O(n*V), plus sorting and copying S elements. Total time is O(n log(n+1)+n*B+S+1), auxiliary O(n+1) including sorted copy/path/stack, output O(B+S). For distinct input, B=2^n. Pruning duplicates does not make the worst case polynomial.

### 11.3 A duplicate-aware fixed-size group

The roadmap also asks for a duplicate-aware combination drill. Reuse the same-depth rule, but save only groups of size k. Availability pruning still counts remaining **occurrences**, including equal ones.

**Contract:** same value/ownership limits as uniqueSelections; validate 0<=k<=n. Return unique size-k value-multiset groups in nondecreasing representation and ascending-choice DFS order. k=0 yields [[]].

```java
static List<List<Integer>> uniqueGroups(int[] values, int k) {
    Objects.requireNonNull(values, "values");
    if (k < 0 || k > values.length) {
        throw new IllegalArgumentException("k outside 0..n");
    }
    int[] a = values.clone();
    Arrays.sort(a);
    List<List<Integer>> result = new ArrayList<>();
    uniqueGroupFrom(a, k, 0, new ArrayList<>(), result);
    return result;
}

private static void uniqueGroupFrom(int[] a, int k, int start,
                                    List<Integer> path,
                                    List<List<Integer>> result) {
    if (path.size() == k) {
        result.add(new ArrayList<>(path));
        return;
    }
    int needed = k - path.size();
    for (int i = start; i <= a.length - needed; i++) {
        if (i > start && a[i] == a[i - 1]) {
            continue;
        }
        path.add(a[i]);
        uniqueGroupFrom(a, k, i + 1, path, result);
        path.remove(path.size() - 1);
    }
}
```

| Input / k | Exact result |
| --- | --- |
| [1,2,2] / 2 | [[1,2],[2,2]] |
| [2,2] / 2 | [[2,2]] |
| [2,2] / 1 | [[2]] |
| [2,2] / 0 | [[]] |
| [3,-1,3] / 2 | [[-1,3],[3,3]] |
| [] / 1 | IAE |

The invariant is a sorted partial group drawn from distinct increasing positions. Soundness allows equal values because their occurrences differ. Completeness retains a canonical earliest feasible representative of every value group. The capacity and sibling checks have separate proofs; neither replaces the other. A useful implementation-specific time bound is O(n log(n+1)+n*V+S+1), with O(n+k+1) working space and O(B+S) output.

### 11.4 Duplicate-aware permutations use a different condition

In permutations, there is no increasing start boundary. The search may choose any unused position. Sort a copy and require equal occurrences to be used in their canonical left-to-right order along a branch:

`i>0 && a[i]==a[i-1] && !used[i-1]`

Skip i when an equal predecessor is still unused. That predecessor could fill this same output position, making the later equal occurrence an equivalent sibling. If the predecessor **is already used in the current prefix**, the later occurrence is a legitimate next copy and must remain eligible.

**Contract:** nonnull int[], n<=8 precondition; duplicates and full-range ints permitted. Input unchanged. Return unique full-length value arrangements in sorted-value DFS order; empty input gives [[]]. State and saved containers are fresh per public call.

```java
static List<List<Integer>> uniqueArrangements(int[] values) {
    Objects.requireNonNull(values, "values");
    int[] a = values.clone();
    Arrays.sort(a);
    List<List<Integer>> result = new ArrayList<>();
    uniqueArrangeFrom(a, new boolean[a.length],
                      new ArrayList<>(), result);
    return result;
}

private static void uniqueArrangeFrom(int[] a, boolean[] used,
                                      List<Integer> path,
                                      List<List<Integer>> result) {
    if (path.size() == a.length) {
        result.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) {
            continue;
        }
        if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) {
            continue;
        }
        used[i] = true;
        path.add(a[i]);
        uniqueArrangeFrom(a, used, path, result);
        path.remove(path.size() - 1);
        used[i] = false;
    }
}
```

For [1,2,2], output is [[1,2,2],[2,1,2],[2,2,1]]. At the root, the second occurrence of 2 is skipped while the first is unused. Under prefix [2] using the first occurrence, the second is allowed. A global “skip every duplicate value” rule would incorrectly remove all full arrangements requiring both 2s.

There are B=n!/product(fi!) unique value arrangements. For this loop-based implementation use O(n log(n+1)+n*V+n*B+1) time: it scans all n positions at every non-base call. Do not assume O(n*B) is always tight after deduplication. With all n values equal, there is one output, but a chain of n non-base states still scans n positions each, giving Θ(n^2) candidate checks. Working space is O(n+1), output O((n+1)*B).

| Duplicate policy | Effect | Why it differs |
| --- | --- | --- |
| Skip equal sibling in a sorted start-index loop | Retain one route for each next value | Ancestor occurrences remain eligible |
| Skip equal permutation choice when prior equal is unused | Canonical ordering of equal occurrence identities | used, not start, determines eligibility |
| Skip an equal value at every depth | Loses [2,2] | Confuses a sibling duplicate with needed multiplicity |
| Deduplicate after exhaustive generation using a set | May produce correct unique results if equality is defined correctly | Still pays for duplicate exploration, snapshots, hashing, and storage |

## 12. Safe pruning

Pruning removes exploration only after a proof shows that the removed branch cannot contribute a required answer—or, for duplicate suppression, that an equivalent canonical branch already covers its logical answers.

A faster program that silently removes valid results is not an optimized implementation of the same contract.

### Distinguish three reasons to stop

| Reason | What has been proved | Example |
| --- | --- | --- |
| Complete solution | This partial representation already meets the output definition | Every subset position decided; save its snapshot |
| Impossible completion | No allowed continuation can succeed | Need three more positions but only two remain |
| Equivalent route | Every logical answer below this choice is represented elsewhere | Later equal sibling after sorting |
| First success in an existence query | One witness suffices for the boolean output | Board word found; still restore state before returning |
| Arbitrary heuristic cutoff | Search is abandoned without a completeness proof | “The branch seems unlikely”; not an exact-search optimization |

A useful pruning proof has the form: **every** allowed continuation satisfies property P, but a valid completion would require not-P. State the constraint that makes P hold.

### Preconditions behind common rules

| Proposed rule | Safe under these assumptions | Counterexample or boundary |
| --- | --- | --- |
| Break when a[j]>remaining | Sorted candidates, all future contributions strictly positive | Unsorted [8,3], remaining=3: breaking at 8 misses [3] |
| Prune a prefix sum greater than target | All permitted remaining contributions are nonnegative, with the rest of the state modeled correctly | [6,-1], target=5: prefix 6 can finish with -1 |
| Stop after reaching sum target | No longer valid completion can add net zero; strict positivity suffices here | With zero allowed, [] and [0] may both be valid for target 0 |
| Remaining target strictly decreases | Every reused candidate is positive | Reusing 0 leaves it unchanged |
| Need more positions than remain | Each remaining input position can be used at most once | Invalid for unlimited reuse of the same candidate |
| Reject a board coordinate already on the route | A cell cannot be reused in one word path | Does not justify permanently forbidding it in all other routes |
| Stop after matching one dictionary word | The query asks only for that one existence result | A multiword trie search may still need longer words extending this prefix |

The signed example is particularly important. A current sum of 6 is not “too large forever” if -1 remains available. Even sorted inputs do not license every overshoot check unless the eligible suffix’s contributions have the needed sign.

For unlimited reusable choices containing both 1 and -1, target 1 admits arbitrarily long nondecreasing multisets: [-1,1,1], [-1,-1,1,1,1], and so on. There may be **infinitely many** answers without a length/supply bound. An invalid positivity assumption can break termination as well as pruning.

The capped sumBundles example still checks positivity. A cap alone would make zero/signed exploration finite, but its “break on too large” and “return at zero” rules would need to be redesigned. Adding a bound does not automatically make the original pruning valid.

### Pruning and result ordering

Changing exploration order may help an existence query find a witness sooner. It does not change which results an exhaustive enumerator must eventually produce. A variable-ordering heuristic needs no completeness loss if every legal choice is still explored; actually omitting choices does.

Before trusting an optimization, compare small exhaustive inputs with an independent unpruned oracle. A counterexample proves a rule wrong; many passing examples supplement but do not replace its proof.

## 13. Board search and path-local visitation

### 13.1 Define the actual path problem

Consider a rectangular character board and one target word. Consecutive letters must occupy orthogonally adjacent cells, and no cell coordinate may be used twice in the same path. Diagonal moves are forbidden.

Original board:

```text
        column 0 1 2
row 0          a b a
row 1          b x c
```

For target "abac", starting at (0,0) and trying **down, right, up, left** first explores b at (1,0), which cannot continue to a new a. That branch must release its marks. A different route succeeds:

(0,0) a → (0,1) b → (0,2) a → (1,2) c.

The first failed b and the later successful b are different cells. More generally, a cell used in a failed route may legally appear in a different attempt. A permanent traversal mark answers a different question.

### 13.2 State and ownership contract

**Public contract for spells:** board/word and every row nonnull; board rectangular; each board/word character in lowercase English a..z. Validate those properties before any empty-word answer. R,C<=8 and L<=12 are preconditions. Empty word returns true: the empty route exists. A nonempty word on an empty/zero-column board returns false. Board contents are unchanged. Repeated calls are independent. Duplicate letters are legal; distinct coordinates remain distinct cells even if read-only input rows alias the same char[].

The helper state is (r,c,at,used):

- Ancestor calls have matched word[0..at) along one non-repeating adjacent route.
- used marks exactly those ancestor coordinates on helper entry.
- The current coordinate is a proposed cell for word[at], not yet marked.
- Return whether this proposal can complete the word.
- Return with used equal to its entry state, on success as well as failure.

The code checks the last matched character as its success base, so it does not make a separate at==L call beyond the word.

```java
private static int validateBoard(char[][] board, String word) {
    Objects.requireNonNull(board, "board");
    Objects.requireNonNull(word, "word");
    int columns = board.length == 0 ? 0
            : Objects.requireNonNull(board[0], "row").length;
    for (char[] row : board) {
        Objects.requireNonNull(row, "row");
        if (row.length != columns) {
            throw new IllegalArgumentException("rectangular board required");
        }
        for (char letter : row) {
            if (letter < 'a' || letter > 'z') {
                throw new IllegalArgumentException("lowercase board required");
            }
        }
    }
    for (int i = 0; i < word.length(); i++) {
        char letter = word.charAt(i);
        if (letter < 'a' || letter > 'z') {
            throw new IllegalArgumentException("lowercase word required");
        }
    }
    return columns;
}

static boolean spells(char[][] board, String word) {
    int columns = validateBoard(board, word);
    if (word.isEmpty()) {
        return true;
    }
    if (word.length() > board.length * columns) {
        return false;
    }
    boolean[][] used = new boolean[board.length][columns];
    for (int r = 0; r < board.length; r++) {
        for (int c = 0; c < columns; c++) {
            if (wordFrom(board, word, r, c, 0, used)) {
                return true;
            }
        }
    }
    return false;
}

private static boolean wordFrom(char[][] board, String word,
                                int r, int c, int at,
                                boolean[][] used) {
    if (r < 0 || r >= board.length
            || c < 0 || c >= board[0].length
            || used[r][c]
            || board[r][c] != word.charAt(at)) {
        return false;
    }
    used[r][c] = true;
    try {
        if (at == word.length() - 1) {
            return true;
        }
        return wordFrom(board, word, r + 1, c, at + 1, used)
                || wordFrom(board, word, r, c + 1, at + 1, used)
                || wordFrom(board, word, r - 1, c, at + 1, used)
                || wordFrom(board, word, r, c - 1, at + 1, used);
    } finally {
        used[r][c] = false;
    }
}
```

The total-cell precheck handles an empty board/zero columns before helpers run and rejects words longer than any no-reuse route. It is only a necessary length condition, not proof that a matching route exists.

### 13.4 Temporary board marking

A second approach stores the path-local mark in the board cell itself. It avoids the separate visited matrix but has a stricter ownership contract.

**Additional preconditions for spellsMarked:** rows are pairwise distinct char[] objects, and the caller permits temporary mutation with no concurrent observer. The same rectangular/lowercase validation applies. Because NUL is outside a..z, it is a safe reserved marker. Board contents are restored before an ordinary completed call returns.

Row independence matters: if two logical rows share one char[] object, marking one coordinate also changes another row’s coordinate. The read-only spells method supports that aliasing; this marked variant does not. That assumption must not be hidden inside a claim of equivalent input contracts.

```java
static boolean spellsMarked(char[][] board, String word) {
    int columns = validateBoard(board, word);
    if (word.isEmpty()) {
        return true;
    }
    if (word.length() > board.length * columns) {
        return false;
    }
    for (int r = 0; r < board.length; r++) {
        for (int c = 0; c < columns; c++) {
            if (markedFrom(board, word, r, c, 0)) {
                return true;
            }
        }
    }
    return false;
}

private static boolean markedFrom(char[][] board, String word,
                                  int r, int c, int at) {
    if (r < 0 || r >= board.length
            || c < 0 || c >= board[0].length
            || board[r][c] != word.charAt(at)) {
        return false;
    }
    char saved = board[r][c];
    board[r][c] = '\0';
    try {
        if (at == word.length() - 1) {
            return true;
        }
        return markedFrom(board, word, r + 1, c, at + 1)
                || markedFrom(board, word, r, c + 1, at + 1)
                || markedFrom(board, word, r - 1, c, at + 1)
                || markedFrom(board, word, r, c - 1, at + 1);
    } finally {
        board[r][c] = saved;
    }
}
```

Short-circuit || does not execute unused later neighbors. It still executes finally in every active matched frame, so a successful route leaves no temporary marks behind. A sentinel that may also appear in valid input would need a different representation or an additional mark mechanism.

| Approach | Visitation meaning | Additional storage | Ownership requirement |
| --- | --- | --- | --- |
| boolean[][] used | Coordinate belongs to current candidate route | O(R+R*C) visited matrix plus O(L) stack | Board stays read-only; aliased input rows are acceptable |
| Temporary board marker | That cell is unavailable in the current route | O(L) stack | Mutable, independently stored rows; reserved marker; restoration |
| Permanent global visited | Coordinate has already been processed for a traversal question | Often O(R*C) | Suits reachability/component contracts, generally not this word-path search |
| Fresh visited copy per child | Each child owns its route exclusion state | Potentially O((R+R*C)*L) live copied matrices | Avoids undo, but copying is real work and memory |

The R term accounts for row-array references/objects; with nonempty columns it is absorbed by R*C. Keeping it prevents “zero cost” claims for many empty rows.

### 13.5 Tests, proof, and costs

Use both board versions on independent-row inputs and compare with an exhaustive coordinate-path oracle. After every success and failure, compare all input characters with a pre-call copy. Repeat the same query to detect stale state.

| Board / word | Expected result |
| --- | --- |
| Original board / "abac" | true; unsuccessful branch then success |
| Original board / "aa" | false; the a cells are not adjacent |
| Original board / "abaca" | false; no legal final a extends any matching abac route |
| Original board / "" | true after validation |
| [] / "" | true |
| [] / "a" | false |
| [[],[]] / "a" | false |
| [["a"]] / "a" | true; single-cell cleanup still occurs |
| [["a","b"],["x","x"]] / "aba" | false; cannot reuse the original a |
| Ragged rows / any word | IAE |
| A null row / "" | NPE; empty word does not bypass validation |
| A board cell 'A' or target "A" | IAE |

**Soundness:** each marked coordinate matches the next required character, is adjacent to the prior one, and is absent from ancestor marks. A last-character success therefore describes a full legal route.

**Completeness:** for any legal word route, the wrapper considers its first coordinate, and the helper considers its next coordinate among the four neighbors. No validity check rejects that route. Restoring marks makes alternate starts/routes eligible again.

**Uniqueness:** this is an existence query, not an enumerator of all routes; one witness suffices. Different routes spelling the same word are not duplicate outputs because only a boolean is returned.

**Termination:** each accepted cell advances at toward L-1. Rejected calls return immediately; no path uses a cell twice. Stack depth is O(L) under this helper’s last-character base. If L>R*C, the wrapper returns before searching.

Validation costs O(R+R*C+L+1). A conservative overall bound is O(R+R*C+L+R*C*4^L+1) for the positive-length search case. Section 15 explains the tighter no-immediate-return branching bound and why O(L) stack does not imply linear search time.

## 14. Soundness, completeness, and uniqueness

A search can finish and still be wrong in three different ways: it can emit an invalid candidate, miss a valid one, or emit the same logical result more than once. Prove the relevant properties separately.

| Property | Question | Typical proof tool |
| --- | --- | --- |
| Soundness | Does every emitted result satisfy all constraints? | Invariant plus the completion/base test |
| Completeness | Can every required logical result be reached? | Follow an arbitrary valid result’s canonical choices; justify every prune |
| Uniqueness | Can two different search routes emit the same logical result? | One-to-one decision encoding or a proved canonical representative |
| Restoration | Does each call return shared working state to its entry value? | Pair each owned mutation with its inverse after the child |
| Termination | Does every branch stop, and are there finitely many branches? | Strict progress measure and finite candidate sets |

Uniqueness is required only when the output contract forbids duplicates. optionTexts intentionally preserves choice-path multiplicity, so equal concatenated text can appear twice. A board boolean has no list of witnesses to deduplicate. State the output identity rule before proving uniqueness.

### A reusable proof structure

1. **Initialization:** show the root represents the empty partial decision sequence and all required choices remain available.
2. **Call invariant:** relate path, used/start/index, remaining target, and constraints. List the exact shared mutations permitted.
3. **Choice validity:** show each accepted edge preserves those relationships.
4. **Base case:** show the snapshot or return value has the requested complete meaning.
5. **Coverage:** take any valid answer and identify its sequence of choices; show that no guard discards its representative.
6. **Uniqueness:** if needed, show either a unique decision route or canonical treatment of equivalent routes.
7. **Restoration:** assume the child returns its entry state; the caller then reverses only its own changes.
8. **Progress:** show that each recursive edge reduces a finite measure or increases depth toward a finite cap.

“Try everything” alone is not a completeness proof. It leaves unanswered what “everything” means, whether legal continuations were accidentally excluded, and whether mutable state from an earlier branch suppressed later choices.

### Proof map for the major patterns

| Pattern | Sound state | Coverage / uniqueness argument | Return-state and progress obligation |
| --- | --- | --- | --- |
| Include/exclude subsets | path contains included positions before i | Any membership set defines one bit vector; distinct values make value subsets unique | Remove included value; n-i decreases |
| Position permutations | used marks exactly positions in path | Any ordering chooses its next unused occurrence; distinct-input orders differ | Remove path tail and clear own used mark; unused count decreases |
| Fixed-size groups | Increasing chosen indexes, size<=k | Each k-position set has one increasing order; capacity prune cannot exclude it | Remove own addition; needed decreases |
| Positive target bundles | Sorted choices, sum(path)+remaining=target, cap respected | Every permitted multiset has a nondecreasing route; sign/sort assumptions justify break | Remove own addition; cap bounds depth, positivity also reduces remaining |
| Duplicate-aware enumeration | Increasing indexes or canonical equal-occurrence order | Keep one equivalent sibling representative while preserving supply for descendants | Restore occurrence marks/path; increase indexes or consume unused supply |
| Board existence | Matched, adjacent, non-repeating coordinate prefix | Wrapper/neighbor loops include every legal route; no witness enumeration required | Restore visit/cell on false and true returns; target position advances |

For duplicate-aware search, saying “sorting removes duplicates” is incorrect. Sorting only makes equivalence visible. The **skip condition and its proof** choose which occurrence route represents each logical result.

For a board query, saying “a cell was already explored” is insufficient. The future options depend on which cells the current route has consumed. Two calls at the same coordinate and target index can have different available continuations because their ancestor-used sets differ.

## 15. Search-tree time and complete space costs

### 15.1 Count what the code actually does

A useful first expression is:

**time = validation/preparation + candidate checks + state updates + output construction.**

If V states perform constant local work, O(V) traversal is reasonable. If every state scans n input positions, use O(n*V). If emitted paths have lengths l1,...,lB, copying costs O(B+sum(li)) including empty result containers. Let S=sum(li).

Calls that immediately fail a boundary/mismatch test are still calls. Output snapshots are still work. A helper returning void can still allocate enormous output through its shared result parameter.

| Quantity | Measures | Does not measure |
| --- | --- | --- |
| V | Total explored helper entries | Maximum stack occupancy |
| D | Maximum simultaneously live helper entries | Number of all branches |
| d | Decisions along the deepest branch | Necessarily the input element count |
| B | Number of output objects/results | Their combined element/character lengths |
| S | Total saved elements/characters | Temporary copies that never become output |
| Maximum path length | One working candidate | Every stored completed candidate |

### 15.2 Generic branching bounds require edge cases

For maximum branching b and maximum decision depth d:

```text
V <= 1 + b + b^2 + ... + b^d

b >= 2: V = O(b^d)
b == 1: V <= d+1
b == 0: only the root can be visited
```

If per-state work is O(1), outputs have length at most d, and B<=b^d, a conservative materializing bound for b>=2 is O(b^d*(d+1)). If each state scans n candidates, add that factor to traversal. This is an upper-bound method, not a claim of a full regular tree or a universal tight recurrence.

Input constraints determine depth. In single-use selections, depth cannot exceed the number of positions. In reusable positive-target search, it can depend on target/minimumPositiveCandidate, subject to any explicit cap. In boards, it depends on word length and no-reuse capacity. Calling all of these “O(2^n)” hides their actual states.

### 15.3 Bounds for these implementations

All rows include constant setup through +1 conventions. Library sorting is covered by the stated preprocessing and O(n) workspace allowance; a sorted copy is real auxiliary storage.

| Example | Search and copying time | Peak auxiliary space | Required output |
| --- | --- | --- | --- |
| selections, n>=1 | Θ(n*2^n); V=2^(n+1)-1, S=n*2^(n-1) | O(n+1) path/stack | Θ(2^n+S) |
| arrangements | O(n*n!+1), including candidate scans/copies | O(n+1) used/path/stack | Θ((n+1)*n!) |
| groups with availability pruning | O(V+k*binomial(n,k)+1), with V<=1+k*binomial(n,k) | O(k+1) | O((k+1)*binomial(n,k)) |
| sumBundles | O(n log(n+1)+V+S+1) | O(n+d+1) | O(B+S) |
| uniqueSelections | O(n log(n+1)+n*B+S+1), V=B | O(n+1) | O(B+S) |
| uniqueGroups | O(n log(n+1)+n*V+S+1) | O(n+k+1) | O(B+S) |
| uniqueArrangements | O(n log(n+1)+n*V+n*B+1) | O(n+1) | O((n+1)*B) |
| optionTexts | O(P+V+A+S+1), P entries, A appended chars | O(M+d+1), M maximum live text | O(B+S) |
| spells | Validation plus actual search calls; conservative O(R+R*C+L+R*C*4^L+1) | O(R+R*C+L+1) | O(1) boolean |
| spellsMarked under its stricter ownership preconditions | Same conservative time | O(L+1) | O(1) boolean |

For n=0, subset/permutation APIs still produce one empty result. For k=0, groups returns one empty group after its constant validation, while uniqueGroups still prepares a sorted copy before the helper. Compare the **actual wrappers**, not just similarly named recurrences.

### 15.4 A tighter board branching account

For a fixed start, at most one matching route prefix has length one. At length two there are at most four choices. At every later step, the immediately preceding cell is already used, leaving at most three candidates before other boundaries/reuse checks.

For L>=1, counts of potentially accepted route prefixes are bounded by:

```text
length 1: 1
length 2: at most 4
length 3: at most 4*3
...
length L: at most 4*3^(L-2), when L>=2

sum = 1 + 4*(1 + 3 + ... + 3^(L-2))
    = 2*3^(L-1) - 1
```

The same formula gives one when L=1. Each accepted nonterminal prefix attempts at most four neighbors, including immediately rejected ones, so rejected calls add a constant factor. Multiply by R*C possible starts and add validation/header costs. This gives a useful tighter upper bound of **O(R+R*C+L+R*C*3^(L-1)+1)** for L>=1.

It remains exponential as a function of L. Geometry, repeated cells, mismatched letters, and first-success short-circuiting reduce actual work. Neither this bound nor the 4^L bound predicts the exact calls in a particular board. For the trace, the measured 10 entries are much smaller.

The length precheck stops when L>R*C. For L=0, both public methods validate inputs and then return true without a DFS; do not substitute zero into a bound with an unexplained exponent L-1.

A separate visited matrix allocates row objects and R*C boolean slots. When R,C>0, its storage is commonly summarized as O(R*C), with O(L) stack added. With zero-width rows, validation still examines R headers. The marked variant avoids that matrix but changes ownership requirements.

### 15.5 Copying state can change peak memory

Compare two designs:

| Design | One active branch | Effect |
| --- | --- | --- |
| Shared path, mutate/undo | One list of at most d elements | O(d) path capacity plus O(d) stack |
| New copied path for each child, ancestors retain their own paths for later siblings | Lists of lengths 0,1,...,d may be live together | O(d^2) live path elements in that design |
| Fresh visited matrix per child, parents retain matrices | Up to one matrix per active depth | O((R+R*C)*d) live copied state |
| Emit a snapshot only at valid output points | Saved objects survive as required output | Account for O(B+S), separate from auxiliary state |

Cumulative allocation over **all** branches is a different quantity again. The fact that copied paths are eventually collected does not make their construction free. Conversely, charging the entire recursion tree as simultaneously live stack overstates memory for ordinary sequential DFS.

ArrayList append is amortized constant time; a resize may copy the current backing contents. Removing the final index does not shift a tail. Snapshot construction copies path references and therefore costs proportional to its length. These collection facts do not remove the cost of output lists themselves.

### 15.6 Depth and numeric safety remain practical constraints

Java does not promise tail-call elimination or a universal safe recursive depth. Finite search can still exceed a runtime’s stack or feasible output memory. The bounded examples keep demonstrations small. For a large-depth use case, consider an explicit stack carrying the same continuation/undo information, a streaming result consumer, or a different algorithm under a changed output contract.

An explicit stack controls call-stack use; it does not make exponential enumeration polynomial. Streaming output reduces retained output memory only if the caller accepts streamed results and does not collect them all again. It still costs time to produce every result.

## 16. Optional constraint satisfaction

This section is **OPTIONAL ADVANCED**, motivated by the roadmap’s C-tier Hard N-Queens problem. It does not block ordinary Backtracking readiness.

Place one queen per row of an n×n board, with no two queens sharing a column or diagonal. State can include the current row, a chosen column for each prior row, and masks recording occupied columns and diagonals.

| Constraint | Key for cell (row,col) | Key range |
| --- | --- | --- |
| Same column | col | 0..n-1 |
| Same row-minus-column diagonal | row-col+n-1 | 0..2n-2 |
| Same row-plus-column diagonal | row+col | 0..2n-2 |

Row uniqueness is automatic when recursion advances one row after each placement. Columns and diagonals need explicit checks. A HashSet can represent sparse occupied keys with expected hashing costs; fixed boolean arrays give direct indexed membership in this bounded domain.

The following is **only a validity helper**, not a complete queen solver. Preconditions: 1<=n<=12, row/col in 0..n-1, arrays sized n,2n-1,2n-1, and masks accurately describe prior placements.

```java
static boolean queenAllowed(int row, int col, int n,
                            boolean[] columns,
                            boolean[] difference,
                            boolean[] sum) {
    return !columns[col]
            && !difference[row - col + n - 1]
            && !sum[row + col];
}
```

If the candidate is allowed, mark the three keys, record the chosen column, explore row+1, and clear exactly those marks when returning. Clearing is safe because the candidate was checked unused before marking, so no earlier queen owns those keys. If marks were already shared, clearing blindly could corrupt an ancestor’s constraints.

### Small state trace, n=4

After placing row 0 at column 1:

- columns={1}
- difference={2}, because 0-1+3=2
- sum={1}, because 0+1=1

| Row 1 candidate | Check | Decision |
| --- | --- | --- |
| col 0 | sum key 1 already occupied | Reject diagonal |
| col 1 | column 1 occupied | Reject column |
| col 2 | difference key 2 occupied | Reject diagonal |
| col 3 | column 3, difference 1, sum 4 all free | Allowed |

A complete valid placement vector is [1,3,0,2]:

```text
.Q..
...Q
Q...
..Q.
```

Its columns are distinct; difference keys are [2,1,5,4] and sum keys [1,4,2,5], also distinct. After exploring this placement and undoing all four rows, all masks should be empty again.

Incremental masks make one candidate validity check O(1). They reduce repeated validation work, not the need to explore many placements. With at most n choices per level and no column reuse, a conservative upper bound for this row/column scanning design is O(n*n!) search work, plus O(n^2*B) if B complete boards are materialized as n strings of length n. Masks, placement vector, and stack use O(n) auxiliary storage; board outputs are separate. The exact visited tree depends on diagonal pruning and implementation details.

```java
static List<Integer> badUndoByValue() {
    List<Integer> path = new ArrayList<>(List.of(9, 4, 9));
    path.remove(Integer.valueOf(9));
    return path;
}
```

Intended restored prefix is [9,4]; actual result is [4,9]. The first equal 9 was removed. Undo the known final position, not a searched value. A fixture with all distinct values may accidentally hide this defect.

### 17.3 A used mark that survives a branch

Preconditions: nonnull distinct input, n<=8. Intended result is all full arrangements as in arrangements.

```java
static List<List<Integer>> badUsedReset(int[] a) {
    List<List<Integer>> result = new ArrayList<>();
    badUsedFrom(a, new boolean[a.length], new ArrayList<>(), result);
    return result;
}

private static void badUsedFrom(int[] a, boolean[] used,
                                List<Integer> path,
                                List<List<Integer>> result) {
    if (path.size() == a.length) {
        result.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) {
            continue;
        }
        used[i] = true;
        path.add(a[i]);
        badUsedFrom(a, used, path, result);
        path.remove(path.size() - 1);
        // Defect: the current choice's used mark remains true.
    }
}
```

For [4,7], actual result is [[4,7]], missing [7,4]. The first full path marked all positions; later siblings find them unavailable. A singleton still works, so that control does not prove restoration. Clearing the caller-owned mark after the child restores its deeper state is the missing obligation.

### 17.4 Suppressing equal values globally

Preconditions: sorted nonnull array, n<=8. Intended policy is the unique value subsets from Section 11.

```java
static List<List<Integer>> badGlobalSkip(int[] sorted) {
    List<List<Integer>> result = new ArrayList<>();
    badSkipFrom(sorted, 0, new ArrayList<>(), result);
    return result;
}

private static void badSkipFrom(int[] a, int start,
                                List<Integer> path,
                                List<List<Integer>> result) {
    result.add(new ArrayList<>(path));
    for (int i = start; i < a.length; i++) {
        if (i > 0 && a[i] == a[i - 1]) {
            continue;
        }
        path.add(a[i]);
        badSkipFrom(a, i + 1, path, result);
        path.remove(path.size() - 1);
    }
}
```

For [1,2,2], actual output is [[],[1],[1,2],[2]], missing [1,2,2] and [2,2]. The guard suppresses the later occurrence at every depth, not only as an equivalent sibling. Compare i to **this call’s eligibility boundary** to distinguish the two cases.

### 17.5 Pruning with an invalid sign assumption

Preconditions: nonnull array, length<=12; valid i in 0..length, accumulated sum fits long. Intended query asks whether a single-use subset of the remaining positions can complete the target.

```java
static boolean badSignedPrune(int[] a, int i, long sum, long target) {
    if (sum > target) {
        return false;
    }
    if (i == a.length) {
        return sum == target;
    }
    return badSignedPrune(a, i + 1, sum + a[i], target)
            || badSignedPrune(a, i + 1, sum, target);
}
```

For [6,-1], i=0, sum=0, target=5, the method returns false although selecting both positions succeeds. The prefix 6 is pruned before -1 can be considered. The code does not have a nonnegative-suffix guarantee. Removing or replacing that prune requires a proof under the actual signed input domain.

### 17.6 Early success bypasses restoration

This small leaf fragment intentionally omits cleanup on one return path. Preconditions: a valid coordinate, nonnull board, desired character; intended behavior leaves the cell unchanged and returns whether this matching cell completes the query.

```java
static boolean badLeafMark(char[][] board, int r, int c,
                           char wanted, boolean last) {
    if (board[r][c] != wanted) {
        return false;
    }
    char saved = board[r][c];
    board[r][c] = '\0';
    if (last) {
        return true;
    }
    board[r][c] = saved;
    return false;
}
```

On board [["a"]], wanted='a', last=true, it returns true but leaves the cell NUL. Calling the query again can now fail. The marked board implementation in Section 13 restores through finally even on a successful return. The control last=false restores correctly, which is why testing only unsuccessful paths misses this error.

### 17.7 Truncating one character after adding many

Preconditions: nonnull prefix/piece. Intended result is the original prefix after simulating append and undo.

```java
static String badBufferRestore(String prefix, String piece) {
    StringBuilder text = new StringBuilder(prefix);
    text.append(piece);
    text.setLength(text.length() - 1);
    return text.toString();
}
```

For prefix="k", piece="ab", actual result is "ka", not "k". For piece="", it removes part of the earlier prefix; empty prefix and piece can throw on a negative length. Save the earlier length and restore that exact value, as optionTexts does.

### 17.8 State persists into a later public call

```java
static final List<Integer> leakedResults = new ArrayList<>();

static List<Integer> badSavedCall(int value) {
    leakedResults.add(value);
    return leakedResults;
}
```

Starting with empty leakedResults, the first call with 4 returns [4]; the second call with 9 returns [4,9] instead of an independent [9]. The first returned reference now also observes [4,9]. This is the same ownership error that static/instance result fields can cause in recursive solution classes. Prefer fresh invocation-owned state when persistence is not requested.

## 18. Choosing another technique

Backtracking is useful when the contract requires choices to be explored, especially constrained enumeration. It is not the default for every problem that admits a recursive description.

| Requirement | Consider | Why it may fit better |
| --- | --- | --- |
| One minimum/maximum from a batch | Scan | No choice tree is required |
| One lookup in a sorted array | Binary search | Ordering proves large regions irrelevant |
| Exact membership among many stored keys | HashSet/HashMap | Repeated equality lookup differs from enumerating arrangements |
| Visit all vertices reachable from a start | Graph DFS/BFS with permanent visited under that contract | Re-exploring every route is unnecessary |
| Shortest unweighted route | BFS | Layer order supplies a distance guarantee that arbitrary first DFS success lacks |
| Count/optimize repeated suffix/amount states | Dynamic programming after defining a sufficient state | Share repeated subproblem answers instead of re-expanding them |
| Generate every legal arrangement | Backtracking or another enumerator | Output itself may already be factorial |
| Select one locally attractive choice | Greedy only with a correctness argument | An appealing heuristic is not proof that alternatives can be discarded |
| Process many dictionary words on one board | Optional trie-guided board search | Prefix structure can reject routes irrelevant to every word |

### Recursion versus DP

Recursion describes control flow. Memoization reuses answers to repeated **complete subproblem states**. Backtracking often carries a path prefix, but two calls with the same numeric remainder need not have the same eligible choices: start, supply, remaining picks, and other constraints may differ.

If the question asks only for a count, a cached suffix count can sometimes be added for many prefixes. If it asks for all actual outputs, those prefixes still have to be combined with suffix results, and output construction remains work. Shared cached mutable result lists also need ownership rules.

For a no-reuse board path, memoizing only (row,col,at) is generally unsound: the current path’s used set affects which future cells are legal. Adding every visited-set detail may create exponentially many states. Do not assume a small cache key is sufficient merely because it is convenient.

The roadmap introduces [1-D DP](./DSA_Interview_Roadmap.md#14-1-d-dynamic-programming) after Backtracking so that repeated-state reasoning has a concrete search baseline. Full DP recurrences are a later topic here.

### Additional pattern bridge: palindrome partitions

The roadmap’s Additional Palindrome Partitioning extends start-index search to **cuts in a string**. At a start position, choose an ending boundary for the next piece, require that piece to be a palindrome, and recurse at the next start. Undo the chosen piece afterward. At the final boundary, copy the piece list.

For original text "noon", valid partitions include ["n","o","o","n"], ["n","oo","n"], and ["noon"]. They are exactly the three valid palindrome partitions. Stopping after finding the complete word would miss the smaller-piece partitions.

The state is a committed partition of the prefix, not a set of used characters. Every valid partition has one increasing cut-boundary sequence, giving coverage and uniqueness. Strings are immutable, but constructing substrings and testing palindromes still costs time. For length n>=1 there are at most 2^(n-1) full cut patterns; a conservative implementation that scans up to n ends and checks up to n characters per visited state can be bounded by O(n^2*2^n), with output costs added. A precomputed palindrome table changes time/space tradeoffs; do not quote one bound without identifying those operations.

This bridge explains the state model without supplying a completed platform implementation.

## 19. Pattern recognition and derivation

### Five recurring patterns

| Pattern | Recognition clue | State and choice rule | Completion / restoration | Main risk |
| --- | --- | --- | --- | --- |
| A — Include/exclude subsets | Every input occurrence has a yes/no decision | index plus chosen prefix; advance index on both branches | Emit when every position is decided; undo an inclusion | Saving aliases or confusing index decisions with numeric targets |
| B — Used-choice permutations | Order matters and each occurrence has limited supply | path plus used positions; try each unused position | Emit full length; undo path and own mark | Permanent used marks; confusing values with positions |
| C — Start-index combinations | Order does not identify a different answer | start plus path; recurse from j or j+1 according to supply | Emit at required size/target; undo path | Wrong reuse boundary, omitted capacity/sign assumptions |
| D — Constrained board DFS | A target follows legal adjacent non-repeating cells | coordinate, target position, path-local used | Return first witness if only existence is needed; clean up on true/false | Permanent visitation, bad bounds, missing early-return cleanup |
| E — Duplicate-aware enumeration | Equal input values exist but logical outputs must be unique | Sorted copy plus depth-local skip or canonical used-occurrence rule | Emit each value answer once; preserve needed multiplicity | Global duplicate suppression or post-dedup cost hidden |

Pattern E is a rule layered onto A/B/C-style enumeration, not a claim that duplicates have one universal template. Pattern D’s constraint state also generalizes to optional queen masks, but its movement/termination rules change.

| Pattern cost reminder | Prefer another approach when |
| --- | --- |
| A: 2^n candidates, copied subset size matters | Only a count such as 2^n is requested with no additional constraint |
| B: n! distinct-input arrangements, n-element snapshots | The desired output is one sorted arrangement or one rank |
| C: Actual candidate checks and depth depend on supply, cap, and target | A count/optimal value has repeated sufficient suffix states suited to DP |
| D: Search branches with target length; visited matrix and stack are separate | Ordinary reachability or shortest unweighted distance is the actual question |
| E: Count actual canonical states plus skipped-candidate scans and copies | The question needs only frequency counts or membership |

Write one sentence for the helper promise. Include its mutation/restoration postcondition. Only then choose Java parameters and base cases. Explain a simple complete search before adding duplicate suppression or pruning. For every omitted branch, state why no required logical result is lost.

## 21. Readiness evidence

Backtracking manages a **partial solution and its eligible continuations**. Recursive DFS is a convenient control flow, but correctness comes from the state contract, legal choice rules, safe pruning, and restoration. A path snapshot preserves an answer; undo preserves future branches. Duplicates require canonical choice reasoning, and complexity must include all search work plus materialized output.

Use the [common readiness rubric](./DSA_Interview_Roadmap.md#common-readiness-rubric-required-for-every-category) together with the Backtracking-specific roadmap demonstration:

- Explain recursion versus DFS versus backtracking, and identify what a call represents in a previously unseen search.
- Define state, choices, validity, completion, output identity, and a progress measure before writing recursion.
- Draw three-value subset and permutation trees; explain outputs, helper calls, and live frames separately.
- Implement the roadmap’s small subset/permutation drills from a blank editor and verify independent output snapshots.
- Derive start eligibility for single-use and reusable choices; prove a target prune under its actual sign assumptions.
- Implement a duplicate-aware group enumerator while retaining [2,2]-style multiplicity.
- Implement a small board-path query and test restoration on failure and early success, including repeated invocations.
- Prove soundness, completeness, and uniqueness where required; explain why each omitted branch is safe.
- Derive time from candidate checks and copied result sizes; report path, used/visited, stack, preparation, and output separately.
- Recognize when the requested result calls for scanning, lookup, BFS/DFS, or later DP instead of exhaustive enumeration.
- Solve changed/unfamiliar variants independently in separate sessions and communicate the contract, proof, tests, and tradeoffs.

**T** requires essential concepts explained without notes. **I** requires tested blank-editor implementation drills. **P** requires independently solved or cold re-solved Essential problems with explanations. **R** requires unfamiliar recognition/transfer and the common communication rubric.
